# ST-Norm 官方训练口径与检索消融收口方案

## 一、问题

1. ST-Norm Base-only 的训练配置是否已经和论文、官方源码对齐。
2. 检索消融是否需要全矩阵；本次只保留 4 组。

## 二、ST-Norm 对齐结论

结构已经对齐，训练此前没有对齐。

官方论文实验集是 BikeNYC、PeMSD7、Electricity，不是 METR-LA。论文与源码共同口径是：

- WaveNet + SNorm + TNorm
- hidden channels=16，kernel=2，blocks=1，layers=4
- Adam，lr=1e-4
- 标准化空间 MSE
- 无 weight decay，无 scheduler

需要保留的项目协议：

- 输入/输出仍是 12 到 12
- 评估指标仍在物理空间报告 MAE/RMSE/MAPE
- Router 训练仍用物理 MAE、lr=5e-4

官方差异处理：

- 论文 batch=4，源码 batch=8，Base-only 采用源码 8
- 官方最多 1000 epoch、每 10 epoch 验证、连续 5 次不提升停止；按本项目统一成本约束最多训练 100 epoch，并在每个 epoch 验证，patience=50。该项是明确的工程上限差异，不宣称机械复现官方训练时长。

## 三、检索消融收口

case study 已经能说明检索器学到了 future-similar 的 key 结构，因此不做全矩阵消融。

只做 METR-LA 上的 4 组对照，变量只有候选排序：

| 组 | 排序 | 下游 | 目的 |
|---|---|---|---|
| random + Router | 随机 encoder key | STAEformer、ARGCN | 去掉学到的检索表示 |
| raw-L1 + Router | 288 步 context L1 | GWN、STAEformer | 去掉学习排序，保留同一日历池和同一 Router |

固定不变：

- weekday_radius1_overlap
- node-level Top-12
- frozen path cache
- 物理 MAE Router
- 不使用 raw_l1_topk_horizon 均匀聚合 mode

## 四、Keep / Remove / Stop

- Keep：ST-Norm Base-only 官方优化口径；4 组检索消融。
- Remove：原四模型全矩阵 random / raw-L1。
- Stop：不再为消融扩更多下游或更多排序变体，除非这 4 组出现和 case study 矛盾的结果。

## 五、raw-L1 的缓存

raw-L1 消融继续使用现有 frozen path cache：按 sample_id 缓存 Base 预测、Top-12 候选、聚合结果和 query key。第一轮填完后，后续 epoch 不再做检索。

额外增加 ContextWindowCache：第一轮 raw-L1 对 288 步候选窗按 event_id 去重后做连续切片读取，避免每个 query 都对整段 series 做 fancy index。第一轮 train/val 填完 frozen cache 后立即释放该窗口缓存。

本机队列 `scripts/run_metrla_retrieval_ablation_queue.ps1` 支持两个互斥开关：`-RandomOnly` 只执行 STAEformer/ARGCN，`-RawL1Only` 只执行 GWN/STAEformer；不带开关时执行全部四组。
