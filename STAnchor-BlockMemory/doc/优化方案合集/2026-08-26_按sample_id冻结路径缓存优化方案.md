# 按 sample_id 的冻结路径缓存优化方案

## 1. 问题与目标

下游采用 `posthoc_frozen_base` 协议时，预训练编码器、Bank 检索、固定 future aggregation 和 base backbone 均不更新。原实现每个 epoch 重复计算这些固定路径，Graph WaveNet/STGCN 单轮约 1,600 秒。

目标是在不改变校正器输入和预测结果的前提下缓存固定路径，并保留原训练协议的 `shuffle=True`。

## 2. 原 batch-index 缓存的问题

旧缓存以 `batch_index` 为键。为了避免 batch 顺序变化导致错位，只能将训练 loader 设置为 `shuffle=False`。这会改变 Adam 的更新顺序，导致缓存版本与原正式版本的首轮 MAE 不可直接比较。

## 3. 新方案

每个样本使用数据集提供的 `sample_id` 作为键：

```text
cache[sample_id] = {
    base_prediction,
    NodeCandidates,
    AggregationOutput,
}
```

一个 batch 首次出现时，先按 batch 计算固定路径，再拆分为逐样本 CPU 条目；之后无论 batch 如何重新排列，都按照当前 batch 的 `sample_id` 重新拼接。这样缓存模式可以继续使用 `shuffle=True`。

## 4. 梯度边界

当前 `RetrievalAwareMHAResidualRouter` 只训练 Router 参数；候选检索、OffsetDecay 聚合和冻结的 backbone 都属于固定路径。因此缓存的候选与聚合输出不包含需要更新的参数，Router 仍在每个 batch 上重新 forward/backward。

## 5. 验证协议与结果

- `research` 环境编译通过；
- 3 batch、2 epoch smoke 运行通过；
- 第 1 epoch 约 2.42 秒，第 2 epoch 约 1.15 秒；
- train/val loss 与 MAE 均为有限值；
- `batches=3/3`，没有减少训练量。

此前严格的固定顺序 A/B 已证明缓存前后数值等价：无缓存固定顺序 MAE `2.877054`，旧缓存固定顺序 MAE `2.877032`，差异 `2.2e-5`。因此当前首轮 `2.828087` 与 `2.877032` 的差异来自训练顺序，而非缓存计算内容。

## 6. 使用与决策

正式训练使用 `--frozen-path-cache`，默认恢复 `shuffle=True`。`--fixed-batch-order` 仅用于缓存等价性对照，不用于最终正式结果。

保留条件：完整训练中候选、aggregation 和 base 输出保持有限，缓存命中后单轮显著缩短，且与同顺序无缓存对照一致。若未来引入可训练 aggregation head，必须缓存其输入而不能缓存其可训练输出。
