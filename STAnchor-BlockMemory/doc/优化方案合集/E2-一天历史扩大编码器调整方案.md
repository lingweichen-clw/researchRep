# E2：一天历史扩大编码器调整方案

更新时间：2026-07-22

## 1. 调整目标

当前检索编码器只接收最近 12 个时间步。METR-LA 的采样间隔为 5 分钟，因此编码器实际只能看到最近 1 小时。设置 `patch_size=3` 后，每个节点只有 4 个时间 token：

$$
P=\frac{T_{\mathrm{ret}}}{p}=\frac{12}{3}=4.
$$

现有诊断显示 learned selector 的 top-1 排序仍弱，说明当前 key 尚未稳定表达“什么样的 context 会产生相似 future”。E2 的目标是验证：

> 当检索编码器能够观察完整一天，并具有足够的隐藏容量时，future-aware retrieval key 是否明显改善。

E2 不修改 selector、候选过滤、历史 future 聚合、confidence 和下游融合。第一版也不加入趋势分解、FFT、ST-Norm 或新的预训练损失。

## 2. 归因边界

E2 同时改变两项设置：

1. 检索历史从 12 步扩大到 288 步。
2. 编码器从 `D=64, L=2, D_r=32` 扩大到 `D=96, L=3, D_r=48`。

因此 E2 只能回答“长历史加扩大编码器的组合是否有效”，不能单独证明收益来自历史长度还是参数量。若 E2 有效，后续必须补充 E1：保持 12 步输入，仅扩大参数量，用于单变量归因。

## 3. 数据窗口

### 3.1 两种 context

对 batch 中第 $b$ 个样本，设预测时刻前最后一个已观测时间为 $t_b$。

检索编码器输入为完整一天：

$$
\mathbf X^{\mathrm{ret}}_b
=
\left[
\mathbf x_{t_b-287},\ldots,\mathbf x_{t_b}
\right]
\in\mathbb R^{288\times N\times C}.
$$

下游预测主干仍只接收最近一小时：

$$
\mathbf X^{\mathrm{pred}}_b
=
\left[
\mathbf x_{t_b-11},\ldots,\mathbf x_{t_b}
\right]
\in\mathbb R^{12\times N\times C}.
$$

真实预测目标保持不变：

$$
\mathbf Y_b
=
\left[
\mathbf x_{t_b+1},\ldots,\mathbf x_{t_b+12}
\right]
\in\mathbb R^{12\times N\times C}.
$$

符号含义：

| 符号 | 含义 | METR-LA 设置 |
|---|---|---:|
| $B$ | batch size | 16 |
| $T_{\mathrm{ret}}$ | 检索历史长度 | 288 |
| $T_{\mathrm{pred}}$ | 下游预测输入长度 | 12 |
| $H$ | 预测长度 | 12 |
| $N$ | 节点数 | 207 |
| $C$ | 输入通道数 | 1 |

### 3.2 未来信息边界

训练、Bank 构建和推理时，`retrieval_x` 的最后时间均为 $t_b$，不得包含 $t_b+1$ 及之后的数据。真实 future $\mathbf Y_b$ 只在预训练时用于构造 future-aware 检索监督，在推理时不可访问。

每个 train/validation/test 窗口必须完整位于自己的时间划分内。E2 不允许 validation 的一天历史向前跨入训练段，也不允许 test 向前跨入 validation 段。这会比 12 步版本少产生部分边界样本，但能保持严格的 split 隔离。

## 4. E2 编码器

### 4.1 Patch 构造

E2 使用 12 步 patch，即每个 token 表示连续 1 小时：

$$
p=12,
\qquad
P=\frac{T_{\mathrm{ret}}}{p}=\frac{288}{12}=24.
$$

窗口归一化和 level features 仍沿用现有实现。归一化后的检索序列为：

$$
\widetilde{\mathbf X}^{\mathrm{ret}}
\in\mathbb R^{B\times288\times N\times C}.
$$

Patch embedding 输出：

$$
\mathbf Z^{(0)}
=
\operatorname{PatchEmbed}
\left(\widetilde{\mathbf X}^{\mathrm{ret}}\right)
\in\mathbb R^{B\times24\times N\times96}.
$$

`PatchEmbed` 同时加入每个 patch 末端对应的 weekday、slot，以及由一天窗口得到的均值、标准差、末值和首末差。

### 4.2 因子化时空编码

E2 保留现有编码顺序，每一层依次执行：

1. 对同一节点的 24 个时间 token 做 temporal self-attention。
2. 对同一 patch 中图边相连的节点做 sparse spatial attention。
3. 使用前馈网络更新隐藏表示。

三层编码后的张量为：

$$
\mathbf H
=
f_{\theta}
\left(\mathbf Z^{(0)},\mathbf A\right)
\in\mathbb R^{B\times24\times N\times96},
$$

其中 $\mathbf A$ 是当前数据集的图结构，$f_{\theta}$ 是三层共享因子化时空编码器。

### 4.3 Retrieval key

注意力池化沿 24 个 patch 聚合节点表示：

$$
\mathbf h_{b,n}
=
\sum_{r=1}^{24}
\alpha_{b,r,n}\mathbf H_{b,r,n},
\qquad
\sum_{r=1}^{24}\alpha_{b,r,n}=1.
$$

节点 key 为：

$$
\mathbf k_{b,n}
=
\operatorname{L2Norm}
\left(\operatorname{MLP}(\mathbf h_{b,n})\right)
\in\mathbb R^{48}.
$$

完整节点 key 张量为 $\mathbf K\in\mathbb R^{B\times N\times48}$。事件 key 仍为节点 key 的均值后再做 L2 归一化，形状为 $B\times48$。

## 5. 参数与训练设置

| 配置 | 当前版本 | E2 |
|---|---:|---:|
| retrieval context | 12 | 288 |
| forecast context | 12 | 12 |
| patch size | 3 | 12 |
| temporal tokens | 4 | 24 |
| hidden dim | 64 | 96 |
| encoder layers | 2 | 3 |
| attention heads | 4 | 4 |
| retrieval dim | 32 | 48 |
| pretraining parameters | 130,979 | 391,836 |
| pretraining batch size | 32 | 16 |
| time mask ratio | 0.25 | 0.25 |
| time mask block | 3 步 | 36 步，即连续 3 小时 |

E2 的 masked reconstruction 和 future-guided retrieval loss 保持不变：

$$
\mathcal L
=
\mathcal L_{\mathrm{mask}}
+
\lambda_{\mathrm{ret}}\mathcal L_{\mathrm{ret}},
\qquad
\lambda_{\mathrm{ret}}=0.1.
$$

由于一天窗口会显著增加 pairwise context distance 的显存占用，batch size 先设为 16。若正式训练发生显存不足，只允许下调 batch size，并必须在实验记录中注明；第一轮不同时引入梯度累积或修改检索损失。

Validation DataLoader 使用由固定随机种子生成的一次性排列，并在所有 epoch 中复用该排列。原因是按时间连续组成的 16 个 E2 validation 样本，其一天历史会全部重叠，导致 non-overlap 过滤后没有合法 retrieval pair。固定随机排列既保留可复现性，也避免 `val_retrieval` 恒为零。该排列只改变同一 validation 集内部的 in-batch 配对，不改变数据划分和样本内容。

## 6. Bank 与下游契约

Bank 中的 learned key 和 level features 由 288 步历史生成。Bank 的 `context_length` 字段表示 retrieval context，因此 E2 Bank 记录为 288。

下游流程分开使用两种输入：

| 模块 | 输入 |
|---|---|
| base forecasting backbone | 最近 12 步 `x` |
| learned retrieval encoder | 288 步 `retrieval_x` |
| raw L1 对照 | 最近 12 步 `x` |
| weekly mean 对照 | 日历和因果过滤后的历史 future |

Bank 校验必须同时检查 encoder fingerprint、图、scaler 和 retrieval context length。旧版 12 步 Bank 不允许与 E2 checkpoint 混用。

## 7. 代码兼容策略

1. `data.context_length` 继续表示下游预测输入长度，保持为 12。
2. 新增可选配置 `data.retrieval_context_length`；缺省时回退到 `context_length`，保证旧配置和旧测试继续工作。
3. 数据集新增 `retrieval_x`、`retrieval_observed`、`retrieval_weekday` 和 `retrieval_slot`。
4. 预训练、Bank、learned retrieval 和 learned diagnostics 使用 retrieval 字段。
5. 下游 backbone 与 raw L1 始终使用原来的 12 步字段。
6. 不修改旧 checkpoint；E2 使用独立 run name、checkpoint 和 Bank 目录。

## 9. 验收标准

### 9.1 工程验收

1. E2 数据 batch 同时包含：
   - `x`: $B\times12\times N\times1$；
   - `retrieval_x`: $B\times288\times N\times1$；
   - `y`: $B\times12\times N\times1$。
2. E2 编码输出为 $B\times24\times N\times96$。
3. 节点 key 为 $B\times N\times48$。
4. masked reconstruction 输出为 $B\times288\times N\times1$。
5. reconstruction、retrieval head 和 encoder 均获得有限且非零梯度。
6. 旧版 `metrla_v1.yaml` 的测试和 checkpoint 构造接口不被破坏。

### 9.2 科学验收

正式预训练和 Bank 构建完成后，使用同一 validation 诊断比较当前版本与 E2：

1. learned top-1 MAE 是否低于当前的 4.4368，并至少不差于 raw L1 top-1 的 4.3493。
2. learned uniform top-K 是否缩小与 raw L1 top-K 的差距。
3. learned weighted top-K 是否稳定优于当前结果 3.9047。
4. learned top-1 与 Oracle top-1 的差距是否缩小。
5. 参数量、每 epoch 时间和峰值显存是否仍在可接受范围。

若 E2 不能改善 learned top-1，也不能改善 weighted top-K，则停止添加频域和 ST-Norm，转而检查 retrieval supervision 与 candidate label。若 E2 明显有效，再补 E1 参数对照，并决定是否进入趋势/残差分解实验。

## 10. 正式实验顺序

1. 预训练 E2。
2. 使用 E2 checkpoint 重建 METR-LA Bank。
3. 运行完整 retrieval diagnostics。
4. 只有 retrieval diagnostics 达标后，才训练 E2 下游模式。
5. 下游阶段至少比较 raw L1 top-K、E2 learned top-K 和 E2 learned top-K + confidence。

本轮不直接运行多 seed。先由单 seed 检索诊断决定是否保留 E2；保留后再进行多 seed 正式确认。

## 13. 数据准备与跨机器排错

### 13.1 是否需要额外数据预处理

E2 不需要单独执行预处理命令。`scripts/pretrain.py` 启动后会自动完成：

1. 读取原始 `METR-LA.h5`。
2. 按时间顺序切分 train、validation 和 test。
3. 只使用训练段拟合节点 scaler。
4. 在线构造 288 步 retrieval context、12 步 forecast context 和 12 步 future。
5. 读取 `adj_mx.pkl`，转换为稀疏图并补充 self-loop。
6. 构造训练和验证 DataLoader。

程序不会自动生成 `METR-LA.h5` 或 `adj_mx.pkl`。这两个原始文件必须事先存在且内容有效。

E2 配置中的相对路径以 `STAnchor-BlockMemory` 项目根目录为基准：

```text
../data/METRLA_data/METR-LA.h5
../data/METRLA_data/adj_mx.pkl
```

例如实验机项目位于 `C:\Users\clw\projects\researchRep\STAnchor-BlockMemory` 时，邻接矩阵实际路径应为：

```text
C:\Users\clw\projects\researchRep\data\METRLA_data\adj_mx.pkl
```

### 13.2 `adj_mx.pkl` 的已知 CRLF 问题

当前 METR-LA 邻接矩阵是 protocol-0 文本 pickle。若传输工具把 LF 换行改写为 CRLF，Python 可能报：

```text
_pickle.UnpicklingError: the STRING opcode argument must be quoted
```

本机有效文件信息为：

```text
Length: 680459 bytes
SHA256: A35687C6E15AA228DC45027B0ED2A0EA0F4EC78F573DEB992C595092D12F61B3
```

实验机检查命令：

```powershell
$graph = "C:\Users\clw\projects\researchRep\data\METRLA_data\adj_mx.pkl"
Get-Item -LiteralPath $graph | Select-Object FullName,Length
Get-FileHash -Algorithm SHA256 -LiteralPath $graph
```

若长度为 681326 字节，基本可以确认文件经历了 LF 到 CRLF 的文本转换。更新后的图加载器会只在这种可逆情况下尝试内存规范化；真正无效的 pickle 仍会报错。更稳妥的处理仍是将本机有效文件压缩为 zip 后以二进制方式传到实验机，避免文本工具修改 `.pkl`。

加载验证：

```powershell
python -c "from stanchor.config import load_config, resolve_project_path; from stanchor.data.graph import load_dense_adjacency; c=load_config('configs/metrla_e2_day96_v1.yaml'); a=load_dense_adjacency(resolve_project_path(c.data.adjacency_path)); print(a.shape, a.dtype, a.min(), a.max())"
```

METR-LA 应输出一个 `207 x 207` 的非负邻接矩阵。该命令通过后再执行正式预训练。
