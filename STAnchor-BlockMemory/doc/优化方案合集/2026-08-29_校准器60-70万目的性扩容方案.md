# HN-OffsetDecay 下游校准器：可部署候选轨迹学习扩容方案（最新）

> 版本：2026-08-29  
> 状态：设计方案，尚未进入代码实现  
> 适用主线：HN-OffsetDecay v1 检索器 + Base-as-candidate 校准器 + `posthoc_frozen_base`

## 1. 方案结论

本次扩容不再把参数主要用于继续加宽 MLP，而是把新增容量放在两个与当前瓶颈直接相关的可学习表示上：

1. **候选完整 residual 轨迹编码（candidate trajectory encoder）**：学习一个历史候选在全部预测 horizon 上的趋势、转折和波动，再把该候选的全局轨迹表示注入每个 horizon 的候选 token。
2. **可学习 horizon 条件表示（horizon embedding）**：为每个预测步提供可学习的 horizon 身份，使同一候选在近端和远端 horizon 上可以产生不同的选择分数。

最终仍采用统一的 Base-as-candidate 残差混合：Base 是第 (K+1) 个零残差候选，历史候选是 residual experts，attention 在 (K+1) 个选项上统一归一化。

本方案明确**不加入固定的数据集身份或 backbone ID embedding**。校准器按目标数据集和目标下游模型重新训练，因此固定 ID 在单次训练中是常数，不能提供可识别的条件信息；应学习的是当前样本的 Base 行为和候选轨迹，而不是记忆标签。

## 2. 背景、职责和边界

### 2.1 模块职责

- HN-OffsetDecay v1 编码器负责从历史上下文构造检索 key，并通过 future-relation 监督学习未来动态相似性。
- Bank 保存历史事件 key、节点 key 和已发生事件的 future payload。
- 下游 backbone（STAEformer、STGCN、Graph WaveNet、ARGCN）产生 (Y^{base})。
- 校准器在目标数据集上重新训练，负责判断当前候选 residual 是否值得施加到 (Y^{base})。

校准器不承担跨数据集参数复用，也不要求一个校准器同时识别多个 backbone。跨数据集能力主要由检索器和候选构造协议验证；校准器只使用目标域部署时可获得的输入。

### 2.2 不改变的内容

以下内容保持不变：

- HN-OffsetDecay v1 encoder、retrieval key 和 Bank schema；
- 周时间槽过滤、因果过滤、node-level Top-K 候选协议；
- OffsetDecay future payload 和候选 mask 语义；
- Base-as-candidate 的统一 (K+1) attention 及 residual aggregation 公式；
- `posthoc_frozen_base`、backbone 冻结策略和 `frozen_path_cache`；
- 数据切分、归一化、训练目标和下游模型接口。

本次只替换校准器内部的候选 token 构造和 horizon 条件表示，并删除当前没有数值作用的 `value_proj` 占位分支。

## 3. 当前结构与具体瓶颈

当前校准器接收：

- `history`: ([B,T,N,C])，当前为 ([B,12,N,1])；
- `base`: ([B,H,N,C])，当前为 ([B,12,N,1])；
- `candidate_futures`: ([B,H,N,K,C])；
- `candidate_masks`: ([B,H,N,K,C])。

当前每个候选的 token 主要由同一 horizon 的局部字段构造：

\[
z_{h,k}^{local}=E_{cand}([
\Delta_{h,k},|\Delta_{h,k}|,s_k,-d_k,p_h]),
\]

其中：

- (Delta_{h,k}=Y^{cand}_{h,k}-Y^{base}_{h}) 是候选相对 Base 的 residual；
- (s_k) 是检索 shape score；
- (d_k) 是 level distance；
- (p_h=h/(H-1)) 是 horizon 位置。

这种构造能看到每一步的 residual，却没有显式建模同一个候选在 (1\ldots H) 步上的整体演变。候选可能在近端方向一致、远端逐渐偏离，或者具有相同水平但不同转折；只看独立的 (Delta_h) 会把这种跨 horizon 关系交给有限的 query/token 点积间接推断。

此外，当前 horizon position 只是标量。需要可学习但仍可解释的 (e_h)，使“候选轨迹”和“预测步位置”成为两个独立可分析因素。

## 4. 最新架构

### 4.1 总体数据流

\[
\begin{aligned}
X^{ctx},Y^{base}&\rightarrow E_{state}\rightarrow S_{q,n},\\
\Delta_{1:H,k}&\rightarrow E_{traj}\rightarrow u_{q,n,k},\\
[Delta_{h,k},|\Delta_{h,k}|,s_k,-d_k,p_h]&\rightarrow E_{local}\rightarrow v_{q,h,n,k},\\
q_{q,h,n}&=W_qS_{q,n}+e_h,\\
z_{q,h,n,k}&=v_{q,h,n,k}+u_{q,n,k}+e_h,\\
z_{q,h,n,base}&=E_{base}(r^{base}_{q,h,n},v^{ctx}_{q,n},p_h,1)+e_h+e_{base},\\
\pi_{q,h,n,:}&=softmax(\text{masked-dot}(q_{q,h,n},z_{q,h,n,:})),\\
\hat Y_{q,h,n}&=Y^{base}_{q,h,n}+\sum_{k=1}^{K}\pi_{q,h,n,k}\Delta_{q,h,n,k}.
\end{aligned}
\]

(u_{q,n,k}) 是候选级的完整轨迹表示，会广播到该候选的所有 horizon；(e_h) 是历史候选和 Base token 共享的 horizon embedding。Base token 仍然是零 residual 候选，不直接贡献数值修正。

### 4.2 State/query encoder

先对 history 的时间维做仅使用观测值的标准化，并与 Base prediction 拼接：

\[
S_{q,n}=E_{state}([Normalize(X^{ctx}_{q,:,n}),Y^{base}_{q,:,n}])
\in\mathbb R^{288}.
\]

每个 horizon 的 query 为：

\[
q_{q,h,n}=W_qS_{q,n}+e_h\in\mathbb R^{384}.
\]

`state_dim=288` 是参数预算平衡后的目标宽度。相对于旧的 320 维 state，减少的参数被用于候选完整轨迹分支；总体仍保持 60--70 万参数，同时新增更直接的候选时序能力。

### 4.3 Candidate local encoder

保留原有可解释的局部字段：

\[
v_{q,h,n,k}=E_{local}([
\Delta_{q,h,n,k},|\Delta_{q,h,n,k}|,s_{q,n,k},-d_{q,n,k},p_h])
\in\mathbb R^{384}.
\]

该分支继续使用部署时已存在的候选 future、检索相似度、level distance 和 horizon 位置，不读取真实 query future。

### 4.4 Candidate trajectory encoder

对同一候选的完整 residual 轨迹沿 horizon 展平：

\[
\Delta^{traj}_{q,n,k}=reshape([
\Delta_{q,1,n,k},\ldots,\Delta_{q,H,n,k}
])\in\mathbb R^{H\times C}.
\]

通过轻量投影：

\[
u_{q,n,k}=E_{traj}(\Delta^{traj}_{q,n,k})
=W_2GELU(W_1\Delta^{traj}_{q,n,k}+b_1)+b_2
\in\mathbb R^{384}.
\]

中间维度为 (d_{traj}=96)。在当前 (H=12,C=1) 时，输入为 12 维。该表示只描述候选整体 residual 轨迹，不单独决定最终权重。

候选 token 组合为：

\[
z_{q,h,n,k}=v_{q,h,n,k}+u_{q,n,k}+e_h.
\]

这使模型可以区分“前 3 步相近、后 9 步发散”和“全程方向一致”的候选，即使二者在某一个 horizon 的局部 residual 相同。

### 4.5 Base token

Base token 不使用固定 model ID，而使用可部署的 Base 行为特征：

\[
x^{base}_{q,h,n}=[r^{base}_{q,h,n},v^{ctx}_{q,n},p_h,1],
\]

其中：

- (r^{base}) 是由 context 和 Base 预测产生的风险代理；
- (v^{ctx}) 是 context 的观测波动性；
- (p_h) 是 horizon 位置；
- 最后一维是 Base token 类型标识。

\[
z_{q,h,n,base}=E_{base}(x^{base}_{q,h,n})+e_h+e_{base}.
\]

`e_base` 只表示“这是 fallback token”，不表示某个数据集或 backbone。

### 4.6 Unified attention 和输出

将 (K) 个历史候选与 1 个 Base token 拼接后，执行共享 token refinement 和 (K+1) 维 softmax：

\[
\ell_{q,h,n,i}=\frac{q_{q,h,n}^{\top}z'_{q,h,n,i}}{\sqrt{384}}
+b_{base}\mathbf 1[i=base],
\]

\[
\pi_{q,h,n,:}=softmax(masked(\ell_{q,h,n,:})).
\]

历史候选 residual 的最终聚合为：

\[
R^{mix}_{q,h,n}=\sum_{k=1}^{K}\pi_{q,h,n,k}\Delta_{q,h,n,k},
\]

\[
\boxed{\hat Y_{q,h,n}=Y^{base}_{q,h,n}+R^{mix}_{q,h,n}}.
\]

Base token 的 residual 恒为 0。无有效历史候选时，历史 token 全部被 mask，Base token 始终有效，输出严格等于 Base。

本方案删除当前 `value_proj` 的死分支。该分支输出乘以 0，不改变预测且梯度恒为 0，不能被称为有效的可学习组件。

## 6. 梯度与未来信息边界

### 6.1 合理的冻结边界

当前 `posthoc_frozen_base` 中：

- backbone 参数冻结，Base forward 在 `no_grad()` 下执行；
- HN encoder、retriever、Bank 和候选构造在 `no_grad()` 下执行；
- `frozen_path_cache` 只保存 detached CPU 的 Base、candidate set 和 aggregation；
- 这些张量搬回 GPU 后，校准器仍可对自身参数正常反向。

缓存 detach 不是校准器内部梯度截断，因为缓存对象不是当前要训练的参数。

### 6.2 校准器内部梯度

forecast loss 直接作用于 `final_prediction`，梯度应经过：

\[
\hat Y\rightarrow\pi\rightarrow q,z'\rightarrow
E_{state},E_{local},E_{base},E_{traj},e_h.
\]

candidate-quality KL 可在训练阶段使用真实 future 构造 teacher，但只作为监督信号；真实 future 不进入 candidate token，也不进入部署阶段 attention 输入。

### 6.3 必须删除的无效路径

不保留：

```python
residual = residual + 0.0 * value_probe
```

当前主公式已经直接聚合真实 candidate residual，不需要无语义的 value projection 占位。

## 7. Loss 和训练策略

第一版不新增 loss：

\[
L=L_{forecast}+\lambda_{quality}L_{quality},
\qquad\lambda_{quality}=0.05.
\]

`L_quality` 仍把 Base error 作为第 (K+1) 个 teacher 选项，temperature 为 0.2。它只在训练阶段计算。真实 query future 只用于 forecast/teacher loss，不作为部署输入。

不恢复旧 risk/blend loss，也不预先加入 usage balance 或熵正则。若 attention 塌缩，再用独立实验验证弱正则。

建议：

- 保持 `posthoc_frozen_base` 和 `frozen_path_cache=true`；
- 先以 `learning_rate=5e-4` 做短验证，并与现有 `1e-3` 对照；
- 保留 `clip_grad_norm_=5.0`，同时记录裁剪前梯度范数和触发比例；
- 使用 best validation MAE checkpoint，不使用最后一轮替代 best。

## 10. 验证协议

### 阶段 A：单 batch 结构和梯度审计

1. 参数量在 690,000--705,000；
2. `trajectory_encoder` 输入 `[B,N,K,H*C]`，输出 `[B,N,K,384]`；
3. attention 为 `[B,H,N,K+1]`，每行和为 1；
4. 候选全部无效时输出等于 Base，Base attention 为 1；
5. 所有新版核心模块获得有限且非零梯度；
6. 不存在 `value_proj` 零梯度占位参数；
7. state dict 保存、加载和结构校验成功。

### 阶段 B：真实缓存路径成本验证

使用真实 `frozen_path_cache=true` 完成 1 个 train epoch 与 1 个 validation epoch，记录：

- epoch 时间、CUDA peak、cache hit rate；
- 校准器 forward 时间；
- 梯度裁剪触发比例。

本机目标每轮不超过 240 秒；实验机目标不超过 180 秒。超时时先定位显存、搬运或轨迹投影，不改变 cache 语义。

### 阶段 C：短轮匹配验证

在相同 Base checkpoint、Bank、seed、batch、候选协议和训练数据范围下比较：

1. 旧 27 万 Base-as-candidate；
2. 新轨迹条件版；
3. 新版去掉 trajectory encoder 的参数匹配对照。

每个下游模型先运行 3--5 轮，记录 overall/horizon MAE、RMSE、Base attention、history mass、attention entropy、candidate-error Spearman、trajectory/correction norm、耗时和显存。

## 11. 判断标准

### 保留

- 相对旧 27 万版 MAE 不退化超过 0.005，且至少一个 horizon 改善；
- attention 随样本/horizon 变化，不塌缩到 Base 或单一候选；
- trajectory 分支梯度非零且有限；
- 单轮成本满足预算；
- 至少两个 downstream backbone 行为一致。

### 持平但可保留

若 (|\Delta MAE|<0.005)，但新组件提高候选轨迹可解释性、梯度完整且成本不增加，可以保留为主线扩容版。论文中表述为“增强跨 horizon 候选表示”，不声称必然提升所有数据集 MAE。

### 删除或回退

- MAE 退化超过 0.02；
- trajectory 分支梯度长期接近 0；
- attention 明显塌缩；
- 时间或显存超过预算；
- 只在一个 backbone 上改善且不能排除协议差异。

## 12. 论文表述

中文：

> 我们在统一的 Base-as-candidate 残差混合器中增加候选完整 residual 轨迹编码和 horizon 条件表示，使校准器能够根据候选未来在整个预测窗口中的演变趋势进行逐 horizon 选择；该表示只使用部署阶段可获得的 Base、检索候选和 context，不依赖目标 future 或固定模型身份。

英文：

> We augment the unified Base-as-candidate residual mixer with a lightweight trajectory encoder and learnable horizon conditioning, enabling horizon-specific selection from the full evolution of each retrieved residual trajectory using only deployment-available context, base forecasts, and retrieved futures.

该表述不声称校准器承担跨数据集泛化；跨数据集泛化仍由 HN-OffsetDecay 检索器和 Bank/候选协议负责验证。

## 13. 最终决策

1. 保留 Base-as-candidate 统一决策和 residual aggregation。
2. 删除无效 `value_proj` 零系数路径。
3. 新增 12→96→384 candidate trajectory encoder。
4. 新增候选、Base 和 query 共享语义的 horizon embedding。
5. `calibrator_state_dim=288`、token width 384，目标参数量约 69.7 万。
6. 不加入固定 dataset/backbone identity embedding。
7. 不改变 HN encoder、Bank、候选协议或 frozen path cache。
8. 先完成单 batch 梯度/shape 审计和缓存成本验证，再进行 3--5 轮匹配实验；未通过则回退旧版。
