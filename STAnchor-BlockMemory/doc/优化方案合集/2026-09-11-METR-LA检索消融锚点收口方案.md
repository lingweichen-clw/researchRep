# METR-LA 检索消融锚点收口方案

## 一、目的与现有证据

本轮实验只回答一个问题：在保持同一个下游 Base、同一个 Router 和同一候选日历池时，预训练检索表示是否优于随机表示和原始轨迹距离。

现有 METR-LA 验证结果为：

| Base | Base-only MAE | Random MAE | Trained MAE | Trained 相对 Random |
|---|---:|---:|---:|---:|
| ST-Norm | 3.114103 | 2.861584 | 2.843111 | 降低 0.018473（约 0.65%） |
| DLinear | 3.912794 | 2.987490 | 2.910324 | 降低 0.077166（约 2.58%） |

结果表明，较弱 Base 留给历史事件校准的误差空间更大，检索方法之间的差异也更容易观察。因此选择 ARGCN 作为完整消融锚点，不再使用较强的 STAEformer 承担该任务。

## 二、术语与对照含义

### 1. Trained retrieval

使用已完成预训练的 HN-OffsetDecay v2 编码器，将每个节点的 288 步历史上下文编码为检索 key。候选先由 `weekday_radius1_overlap` 构造合法日历池，再按学习 key 排序并保留 node-level Top-12。

### 2. Random retrieval

使用与主模型结构相同、但未经预训练的随机初始化编码器生成 key。历史事件、候选 future、日历协议、Top-12、Router、Base checkpoint 和下游训练配置均与 Trained retrieval 保持一致。它用于判断收益是否来自预训练学到的检索表示，而不是随机高维映射或 Router 本身。

### 3. Raw-L1 retrieval

对 Query 与合法历史候选在同一节点上的 288 步归一化原始上下文计算平均 L1 距离，并选择距离最小的 Top-12。它不使用学习 key，也不执行 Query 编码器前向；选出的候选与主方法一样经过 OffsetDecay 后送入 Router。Bank 仅提供因果历史事件、原始候选上下文、候选 future 和缓存索引。

### 4. 未来信息边界

三种检索在部署时都只使用 Query context 和历史 Bank。候选必须满足因果约束，Query 的真实 future 只用于下游训练损失和离线验证指标，不参与候选筛选。

## 三、最终实验矩阵

### ARGCN 完整消融链

1. ARGCN Base-only（已有）。
2. ARGCN + Trained retrieval + Router（已有或正式主实验）。
3. ARGCN + Random retrieval + Router（本机队列）。
4. ARGCN + Raw-L1 retrieval + Router（本机队列）。

### GWN 辅助对照

保留 GWN + Raw-L1 retrieval + Router，用于检查 raw-L1 结论是否只在 ARGCN 上出现。

不再运行 STAEformer random 或 raw-L1。本机队列总计三组：ARGCN random、ARGCN raw-L1、GWN raw-L1。

## 四、严格匹配项

同一 Base 内比较时保持以下项目一致：METR-LA 数据划分与归一化、Base checkpoint、Router 架构、physical MAE、batch size 32、学习率 0.0005、50 epochs、关闭 early stopping、`weekday_radius1_overlap`、node-level Top-12 和 frozen path cache。

唯一主动变量是候选排序来源：trained key、random key 或 raw 288-step L1。

## 五、实现范围与停止条件

新增 `configs/ablation_rawl1_offset_decay_router_argcn.yaml`，并更新 `scripts/run_metrla_retrieval_ablation_queue.ps1` 的任务列表。Raw-L1 与 learned selector 均使用 OffsetDecay 候选载荷；检索实现、Router、Bank 格式和缓存机制保持不变。

完成三组实验后停止扩展 random/raw-L1 消融。若 ARGCN 上 Trained 同时优于 Random 与 Raw-L1，则完整链支持预训练表示价值；若只优于其中之一，则按对应对照边界陈述；若均不优于，则保留真实结果并转向分析检索排序，而不是继续增加 Base 数量。
