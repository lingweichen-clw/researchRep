# E2 预训练加速优化方案

更新时间：2026-07-23

## 1. 目标和边界

E2 在实验机上的完整训练耗时为 7 小时 00 分 31 秒，平均每轮 10.78 分钟。单次训练可以接受，但多 seed、消融和迁移预训练会迅速放大成本。

本方案只解决一个问题：

> 在不改变一天历史、时空编码器、future-guided 正负样本语义和下游接口的前提下，降低 E2 的训练时间与峰值显存。

本轮不加入 ST-Norm、频域分解、新 decoder 或新损失。优化必须逐项实施、逐项验收；未产生可测收益的优化应删除。

目标分两级：

| 目标 | 当前 | 第一阶段目标 | 第二阶段目标 |
|---|---:|---:|---:|
| 平均 epoch 时间 | 10.78 分钟 | 不高于 8.0 分钟 | 不高于 6.5 分钟 |
| 39 epoch 等价耗时 | 7.01 小时 | 不高于 5.2 小时 | 不高于 4.3 小时 |
| learned Top-K MAE | 3.7600 | 不明显退化 | 不明显退化 |

“不明显退化”在本方案中定义为：同 seed 完整诊断的 learned weighted Top-K MAE 不高于 3.8000，learned Top-1 MAE 不高于 4.3100，并继续优于 raw-L1 Top-K。

## 2. 当前计算负担来自哪里

### 2.1 全分辨率批内两两距离

归一化的一天历史为：

$$
\widetilde{\mathbf X}
\in\mathbb R^{B\times T_{\mathrm{ret}}\times N\times C}
=
\mathbb R^{16\times288\times207\times1}.
$$

当前实现通过广播计算 batch 内任意事件 $i,j$ 在每个节点 $n$ 上的 context MAE：

$$
d^{X}_{i,j,n}
=
\frac{
\sum_{t=1}^{T_{\mathrm{ret}}}\sum_{c=1}^{C}
M_{i,t,n,c}M_{j,t,n,c}
\left|widetilde X_{i,t,n,c}-\widetilde X_{j,t,n,c}\right|
}{
\sum_{t=1}^{T_{\mathrm{ret}}}\sum_{c=1}^{C}
M_{i,t,n,c}M_{j,t,n,c}
}.
$$

$M_{i,t,n,c}\in\{0,1\}$ 表示该位置是否真实有观测。广播中间张量形状为：

$$
B\times B\times T_{\mathrm{ret}}\times N\times C
=16\times16\times288\times207\times1.
$$

元素数为：

$$
16\times16\times288\times207
=15{,}261{,}696.
$$

单个 float32 中间张量约占 58.2 MiB。实际计算还会同时出现差值、绝对值、共同观测掩码和临时归约张量，因此峰值显存高于 58.2 MiB。

### 2.2 clean 与 masked 双视图编码

每个训练 batch 同时编码：

1. clean view，用于 retrieval key；
2. masked view，用于重建。

两者拼接后的 encoder 输入为：

$$
\mathbf Z_{\mathrm{both}}
\in\mathbb R^{2B\times P\times N\times D}
=
\mathbb R^{32\times24\times207\times96}.
$$

三层时空编码器的 attention、FFN 和反向传播都在该双倍 batch 上执行。因此训练耗时不能只归因于 pairwise 距离；必须先测量 encoder、pairwise label、backward 和数据传输各自占比。

## 3. 总体策略

采用以下收敛顺序：

1. **P0：固定批次性能剖析。** 只测量，不改算法。
2. **O1：受控混合精度。** 不改变目标与样本。
3. **O2：精确分块 pairwise MAE。** 不改变距离公式和正负样本标签。
4. **O3：随机任务路由。** 只有 O1+O2 仍不达标时才启用；保持综合目标的期望梯度不变，但会增加梯度方差。

不得一次同时启用 O1、O2、O3，否则无法判断速度收益和数值偏差来自哪一项。

## 4. P0：固定批次性能剖析

### 4.1 测量内容

使用固定 seed 和 100 个正式训练 batch，前 10 个 batch 作为 warm-up，不写入正式实验结果。通过 CUDA Event 分别统计：

| 阶段 | 含义 |
|---|---|
| data | CPU 取 batch 与 host-to-device 传输 |
| clean/masked forward | embedding、三层 encoder、retrieval/reconstruction head |
| pairwise labels | context/future distance、分位数、positive/hard-negative mask |
| retrieval logits | node key 相似度与 log-sum-exp |
| backward + step | 反向传播、梯度裁剪和 AdamW 更新 |

同时记录：

$$
\text{peak memory}
=
\operatorname{max\_memory\_allocated()}.
$$

### 4.2 决策规则

- pairwise labels 占 batch 时间超过 20%：优先实施 O2。
- encoder forward/backward 占比最高：优先实施 O1。
- data 阶段超过 10%：再单独测试 `num_workers`、pinned memory 和 non-blocking copy。
- 禁止仅凭张量尺寸猜测瓶颈后同时修改全部路径。

## 5. O1：受控混合精度

### 5.1 做法

只对 embedding、encoder 和线性 head 的前向传播启用 autocast：

1. GPU 支持 BF16 时优先使用 BF16；
2. 否则使用 FP16 和 `GradScaler`；
3. pairwise 距离、`nanquantile`、retrieval logits、`logsumexp` 和最终 loss 强制转回 FP32。

保持 FP32 的原因是检索损失包含分位数、极小 softmax temperature 和掩码后的 $-\infty$，这些操作比普通线性层更容易在 FP16 下出现排序抖动、上溢或下溢。

### 5.2 科学边界

O1 不改变：

- 输入窗口；
- mask 策略；
- 正负样本定义；
- loss 权重；
- 模型参数量；
- Bank 和 checkpoint 接口。

### 5.3 验收

在同一个固定 batch 上比较 FP32 与 AMP：

1. total、mask、retrieval loss 均有限；
2. 相对损失偏差不超过 $10^{-3}$；
3. positive/hard-negative mask 完全一致，因为标签路径仍为 FP32；
4. 100 batch 平均耗时至少下降 20%，否则删除 O1；
5. 峰值显存下降至少 20%。

## 6. O2：精确分块 pairwise MAE

### 6.1 数学等价计算

将 288 步划分成 $Q$ 个连续小块 $\mathcal I_q$。例如块长 $L=36$ 时：

$$
Q=\frac{288}{36}=8.
$$

对每个块只构造：

$$
\mathbf A^{(q)}
\in\mathbb R^{B\times B\times L\times N\times C},
$$

并累计分子与共同观测数：

$$
S_{i,j,n}
=
\sum_{q=1}^{Q}
\sum_{t\in\mathcal I_q}\sum_c
M_{i,t,n,c}M_{j,t,n,c}
\left|\widetilde X_{i,t,n,c}-\widetilde X_{j,t,n,c}\right|,
$$

$$
C_{i,j,n}
=
\sum_{q=1}^{Q}
\sum_{t\in\mathcal I_q}\sum_c
M_{i,t,n,c}M_{j,t,n,c},
$$

$$
d^X_{i,j,n}
=
\frac{S_{i,j,n}}{\max(C_{i,j,n},1)}.
$$

这里每个符号的含义如下：

- $i,j\in\{1,\ldots,B\}$：同一个训练 batch 中的两个历史事件。$i$ 是被比较的 query event，$j$ 是候选 event。
- $n\in\{1,\ldots,N\}$：交通传感器节点。
- $t\in\{1,\ldots,T_{\mathrm{ret}}\}$：一天 retrieval context 中的时间步；$\mathcal I_q$ 是第 $q$ 个时间块包含的时间步集合。
- $c\in\{1,\ldots,C\}$：输入通道；METR-LA 只有速度一个通道，所以 $C=1$。
- $\widetilde X_{i,t,n,c}$：事件 $i$ 在时间 $t$、节点 $n$、通道 $c$ 的训练集标准化值，来自 `retrieval_x`，不是未来值。
- $M_{i,t,n,c}\in\{0,1\}$：**原始数据观测掩码**。$M=1$ 表示该位置有真实观测，$M=0$ 表示该位置缺失或被数据规则判定为无效。它不是预训练阶段随机生成的人工时间/空间 mask。
- $M_{i,t,n,c}M_{j,t,n,c}$：共同观测指示量。只有事件 $i$ 和事件 $j$ 在同一位置都有效时，该位置才参与距离累加。
- $S_{i,j,n}$：事件 $i,j$ 在节点 $n$ 上所有共同观测位置的绝对差之和，形状为 $B\times B\times N$。
- $C_{i,j,n}$：事件 $i,j$ 在节点 $n$ 上的共同有效观测数量，形状为 $B\times B\times N$。
- $d^X_{i,j,n}$：节点级 masked L1 context 距离，形状为 $B\times B\times N$。当 $C_{i,j,n}=0$ 时该 pair 没有有效比较位置，代码会将它标记为无效，而不是把分母保护值 1 当作真实观测数量。

因此，$M_iM_j$ 的作用是“只在双方都看得到的位置比较”，避免某一事件缺失值被误当成真实的 0 参与距离。该方法没有把一天历史压缩成均值或 patch 特征，仍逐时间步计算完全相同的 masked L1 距离；唯一差异是浮点加法顺序。

块长 36 时，最大的五维 float32 临时张量约为：

$$
16\times16\times36\times207\times1
=1{,}907{,}712
$$

个元素，即约 7.3 MiB，为原张量的八分之一。

### 6.2 实施约束

- `pairwise_time_chunk` 必须是配置项，默认 `null` 表示旧实现。
- future 只有 12 步，先保持原实现，避免无收益的代码扩散。
- 累加器固定为 FP32。
- 不修改 quantile、positive 或 hard-negative 规则。

### 6.3 验收

对固定真实 batch 比较旧实现和分块实现：

1. distance 满足 `allclose(rtol=1e-5, atol=1e-6)`；
2. valid pair、positive pair 和 hard-negative mask 完全一致；
3. retrieval loss 满足 `allclose(rtol=1e-5, atol=1e-6)`；
4. 峰值显存至少下降 30%；
5. 若 batch 时间没有下降至少 10%，但显存已明显下降，则只在显存受限配置启用；若时间和显存都无明显收益，则删除该实现。

## 7. O3：随机任务路由，仅作为第二阶段

### 7.1 动机

当前每个 batch 都执行 clean 和 masked 两次编码视图。若 O1+O2 后 epoch 仍超过 8 分钟，可在训练阶段随机选择一个任务：

$$
J\sim\operatorname{Bernoulli}(p_{\mathrm{mask}}),
\qquad p_{\mathrm{mask}}=0.5.
$$

随机损失估计量为：

$$
\widehat{\mathcal L}
=
\frac{\mathbb I[J=\mathrm{mask}]}{p_{\mathrm{mask}}}
\mathcal L_{\mathrm{mask}}
+
\frac{\mathbb I[J=\mathrm{retrieval}]}{1-p_{\mathrm{mask}}}
\lambda_{\mathrm{ret}}\mathcal L_{\mathrm{ret}}.
$$

其中 $\mathbb I[\cdot]$ 是指示函数。它满足：

$$
\mathbb E\left[\widehat{\mathcal L}\right]
=
\mathcal L_{\mathrm{mask}}
+\lambda_{\mathrm{ret}}\mathcal L_{\mathrm{ret}}.
$$

因此期望优化目标与原模型相同，但单个 batch 只经过一个 encoder view，代价是梯度方差增大、每个 head 每轮接收的更新次数约减半。

### 7.2 实施边界

- 只在 training 使用随机路由；validation 仍在每个 batch 上计算两个任务，保证 early stopping 指标可比。
- 不同时修改学习率、batch size 或 loss 权重。
- 记录每轮 mask/retrieval batch 数，防止随机比例失衡。
- 第一版固定 $p_{\mathrm{mask}}=0.5$，不做概率搜索。

### 7.3 验收

1. 100 batch 训练耗时相对原 FP32 基线至少下降 35%；
2. 3 epoch 小规模对照中无 NaN、梯度爆炸或某个 head 无更新；
3. 只有前两项通过，才运行一个 seed 的完整预训练和 retrieval diagnostics；
4. learned weighted Top-K MAE 不高于 3.8000，learned Top-1 不高于 4.3100；
5. 未达到质量门槛则删除 O3，保留 O1/O2，不继续调路由概率。

## 8. 条件性数据管线优化

只有 P0 显示 data 阶段超过 10% 时，才依次测试：

1. `num_workers=2`；
2. DataLoader `pin_memory=True`；
3. `.to(device, non_blocking=True)`；
4. `num_workers>0` 时启用 `persistent_workers=True`。

Windows DataLoader 会使用 spawn，过多 worker 可能复制数据并增加启动成本。每次只改变一个设置，以 100 batch 中位耗时决定保留或删除。

## 9. 暂不采用的方案

### 9.1 暂不把 288 步压缩成 patch 均值计算 hard negative

该方法能将 pairwise 时间维从 288 降到 24，但会把“全分辨率 context 相似”改成“小时级摘要相似”，从而改变时空海市蜃楼负样本定义。只有精确工程优化全部不达标时，才能将其作为单独的预训练监督消融，而不能伪装成纯加速。

### 9.2 暂不优先使用 `torch.compile`

当前空间注意力包含 `scatter_reduce_` 和 `scatter_add_`，Windows、PyTorch、CUDA 和 Triton 组合下的编译兼容性不稳定。先完成可解释、可回退的 O1/O2；只有 profiler 仍显示大量 Python/launch overhead 时再单独评估。

### 9.3 不降低一天历史和模型容量

本次完整诊断已证明 E2 learned retrieval 优于旧版。直接缩短历史或缩小编码器虽然会加速，但会重新打开已经关闭的表示能力问题，不属于本轮工程优化。

## 10. 实施顺序和停止条件

| 阶段 | 唯一改动 | 通过后 | 失败后 |
|---|---|---|---|
| P0 | 增加性能计时 | 确认主瓶颈 | 不做猜测性优化 |
| O1 | AMP，loss 标签保持 FP32 | 保留并进入 O2 | 删除 AMP |
| O2 | 精确分块 context MAE | 达到 8 分钟则停止 | 无收益则删除 |
| O3 | 训练期随机任务路由 | 达标后做完整诊断 | 删除 O3，不继续扩展 |

明确停止条件：若 O1+O2 已将 epoch 降到 8 分钟以内，就不实施 O3；若 O3 破坏检索质量，就接受 8 分钟级训练成本，不再通过修改 proxy task 追求速度。

## 11. 与当前结果的关系

当前 epoch 29 checkpoint、E2 Bank 和 3.7600 的诊断结果仍然有效，不需要为了加速方案重新解释。加速优化服务于后续多 seed、E1 参数归因和迁移实验；新实现必须使用新的 run name，不能覆盖当前正式产物。
