# E4 检索一致性关系预训练改进方案（暂缓）

> 本文是上一轮候选收缩假设的历史方案。METR-LA 同域 trained-vs-random 与 PEMS-BAY `level_weight=0` 归因完成后，当前不执行本文的同 weekday-slot-only 候选收缩。现行下一步方案见 `E4-目标域自适应关系预训练方案.md`。

## 1. 改进动机

PEMS-BAY target-random 对照已经证明：当前 METR-LA E3 source-pretrained key 没有优于同构 random key。learned weighted Top-K 的 future MAE 分别为 2.209414 和 2.173856；horizon-only 下游 MAE 分别为 1.881369 和 1.878035。

因此 E4 不再增加编码器层数、频域分支、图模块或新 selector。下一步只处理一个最接近失败证据的问题：

> 训练关系损失所比较的候选，是否与模型真正部署时需要排序的候选一致？

本方案采用“先排除分数组合问题，再改候选集合”的两阶段顺序。每一阶段都有明确停止条件。

## 2. 当前保持不变的部分

以下内容与当前 E3 完全相同：

- 一天历史输入，$T=288$；
- patch size、时空 encoder、retrieval head 和 48 维 key；
- 掩码重建任务及其 decoder；
- future relation teacher 和 student 的分布蒸馏形式；
- PEMS-BAY Bank payload、日历索引和节点级 Top-K 聚合；
- 下游 backbone、horizon fusion 和 confidence；
- 单源 METR-LA 预训练、同类型 PEMS-BAY 迁移的研究边界。

E4 不增加模型参数，只改变关系损失中“哪些事件可以互相比较”。

## 3. 阶段 A：先隔离固定 level score

### 3.1 唯一变量

当前节点重排分数为：

$$
s_{i,j,n}
=
\operatorname{cos}
\left(\mathbf{k}_{i,n},\mathbf{k}_{j,n}\right)
+
\lambda_{\ell}
\exp\left(-d^{\ell}_{i,j,n}/\tau_{\ell}\right).
$$

其中：

- $i$ 是 query 事件；
- $j$ 是历史候选事件；
- $n$ 是节点；
- $\mathbf{k}_{i,n},\mathbf{k}_{j,n}\in\mathbb{R}^{48}$ 是节点 key；
- $d^{\ell}_{i,j,n}\in\mathbb{R}_{\ge 0}$ 是四类 level 统计量的平均绝对距离；
- 当前 $\lambda_{\ell}=0.25$，$\tau_{\ell}=1$。

阶段 A 只令 $\lambda_{\ell}=0$。Bank、checkpoint、候选日历过滤、Top-K、温度和 validation query 全部保持不变，不重新训练模型，也不重建 Bank。

### 3.2 比较对象

分别用以下两套 key 运行完整 PEMS-BAY validation 检索诊断：

1. METR-LA E3 source-pretrained key；
2. target-random key。

只比较 `learned_top1`、`learned_uniform_topk` 和 `learned_topk` 的 future MAE，同时记录 Top-1 weight 与 $K_{\mathrm{eff}}$。

### 3.3 决策

- 若 $\lambda_{\ell}=0$ 后 source 的 learned Top-K MAE 低于 random，则问题主要来自 level score 与 key score 的混合。保留 E3 encoder，删除 level 项，并只训练一次 source horizon-only 验证最终 MAE；不实施 E4 损失修改。
- 若 source 仍不优于 random，则确认 key 本身缺少目标域判别力，进入阶段 B。
- 不扫描多个 level weight。阶段 A 只比较 `0` 与已经完成的 `0.25`，避免把 validation 变成调参集。

## 4. 阶段 B：E4 检索一致性候选关系

### 4.1 当前 E3 的候选问题

设一个预训练 batch 中有 $B$ 个事件、$N$ 个节点。E3 节点 key 为：

$$
\mathbf{K}
\in
\mathbb{R}^{B\times N\times D},
$$

其中 $D=48$。

E3 只用“不重叠且非自身”构造 batch 内关系候选，没有使用 weekday-slot，也同时允许 anchor 之前和之后的事件。实际部署却只在同 weekday-slot 的严格历史事件中排序。模型训练了大量部署阶段不会出现的竞争关系。

### 4.2 E4 候选集合

对 anchor 事件 $i$，定义：

$$
\mathcal{V}^{\mathrm{E4}}_i
=
\left\{
j\;\middle|\;
d_j=d_i,
\;s_j=s_i,
\;t^{\mathrm{future\_end}}_j<t^{\mathrm{context\_start}}_i
\right\}.
$$

符号含义：

- $d_i,d_j\in\{0,\ldots,6\}$：事件上下文末端对应的 weekday；
- $s_i,s_j\in\{0,\ldots,287\}$：事件上下文末端对应的五分钟时间槽；
- $t^{\mathrm{context\_start}}_i$：anchor 一天上下文的起始时间索引；
- $t^{\mathrm{future\_end}}_j$：候选历史 future 的结束时间索引；
- 条件 $t^{\mathrm{future\_end}}_j<t^{\mathrm{context\_start}}_i$ 保证候选在 anchor 一天输入开始前已经完整发生。

这里使用与 Bank 检索完全相同的 `query_weekday`、`query_slot` 和因果边界，不重新定义另一套时间槽。

### 4.3 Future teacher

future 张量为：

$$
\mathbf{Y}
\in
\mathbb{R}^{B\times H\times N\times C},
$$

其中 $H=12$，$C=1$。先用各自 context 的均值和标准差归一化：

$$
\widetilde{Y}_{i,h,n,c}
=
\frac{Y_{i,h,n,c}-\mu^{X}_{i,n,c}}
{\sigma^{X}_{i,n,c}+\varepsilon}.
$$

$\mu^{X},\sigma^{X}\in\mathbb{R}^{B\times N\times C}$ 来自每个事件自己的 288 步 context，不使用 validation 或 test 统计量。

对 $j\in\mathcal{V}^{\mathrm{E4}}_i$，定义节点 future 距离：

$$
d^{Y}_{i,j,n}
=
\frac{
\sum_{h=1}^{H}\sum_{c=1}^{C}
M_{i,j,h,n,c}
\left|
\widetilde{Y}_{i,h,n,c}-\widetilde{Y}_{j,h,n,c}
\right|
}{
\sum_{h=1}^{H}\sum_{c=1}^{C}M_{i,j,h,n,c}
}.
$$

其中 $M_{i,j,h,n,c}=1$ 表示两个 future 在该位置都有有效观测，否则为 0。距离矩阵 $\mathbf{D}^{Y}\in\mathbb{R}^{B\times B\times N}$，但只计算或保留 E4 合法候选位置。

teacher 分布为：

$$
q^{Y}_{i,j,n}
=
\frac{
\exp\left(-d^{Y}_{i,j,n}/\tau_T\right)
}{
\sum_{r\in\mathcal{V}^{\mathrm{E4}}_i}
\exp\left(-d^{Y}_{i,r,n}/\tau_T\right)
},
\qquad j\in\mathcal{V}^{\mathrm{E4}}_i.
$$

$q^{Y}_{i,j,n}$ 表示候选 $j$ 的未来形状对 anchor $i$、节点 $n$ 的相对相似程度。它只在预训练时构造监督，不进入 Bank，也不会在推理时读取真实未来。

### 4.4 Key student

节点 key 的 cosine 相似度为：

$$
a^{K}_{i,j,n}
=
\frac{
\mathbf{k}_{i,n}^{\top}\mathbf{k}_{j,n}
}{
\|\mathbf{k}_{i,n}\|_2\|\mathbf{k}_{j,n}\|_2
}.
$$

student 分布为：

$$
p^{K}_{i,j,n}
=
\frac{
\exp\left(a^{K}_{i,j,n}/\tau_S\right)
}{
\sum_{r\in\mathcal{V}^{\mathrm{E4}}_i}
\exp\left(a^{K}_{i,r,n}/\tau_S\right)
}.
$$

$p^{K}_{i,j,n}$ 是 encoder-selector 在同一个真实候选集合上的排序概率。E4 关系损失仍使用交叉熵：

$$
\mathcal{L}_{\mathrm{relation}}^{\mathrm{E4}}
=
-\frac{1}{|\mathcal{A}|}
\sum_{(i,n)\in\mathcal{A}}
\sum_{j\in\mathcal{V}^{\mathrm{E4}}_i}
q^{Y}_{i,j,n}\log p^{K}_{i,j,n},
$$

其中 $\mathcal{A}$ 是至少拥有两个合法历史候选且 future 有效的 anchor-node 集合。

总损失保持 E3 形式：

$$
\mathcal{L}
=
\mathcal{L}_{\mathrm{mask}}
+
\lambda_{r}\mathcal{L}_{\mathrm{relation}}^{\mathrm{E4}}.
$$

首轮保持 $\lambda_r$、$\tau_T$ 和 $\tau_S$ 不变，只隔离候选集合这一项改动。

## 5. Calendar-group 训练组织

普通随机 batch 中，同 weekday-slot 的事件可能太少。E4 不引入 memory queue，而是改变 sampler：

1. 在 METR-LA 训练段按 `(query_weekday, query_slot)` 建立索引；
2. 一个 calendar group 包含该 weekday-slot 在不同历史周的事件；
3. 一个优化 batch 可拼接多个 calendar group；
4. 关系掩码只允许同 group 且位于 anchor 之前的事件，跨 group 不参与关系损失；
5. 掩码重建仍使用整个 batch，不受 group 限制。

若一个 batch 拼接 $G$ 个 calendar group，每组最多 $R_g$ 个事件，总事件数为 $B=\sum_{g=1}^{G}R_g$。模型输入和输出形状仍为：

$$
\mathbf{X}\in\mathbb{R}^{B\times288\times N\times C},
\qquad
\mathbf{K}\in\mathbb{R}^{B\times N\times48}.
$$

这只改变样本编组和关系 mask，不改变 encoder 张量流。

## 6. Event Top-R 的处理

PEMS-BAY 当前合法候选数为 11 至 13，而 `event_top_r=32`，所以事件级检索没有截断候选。E4 首轮不优化 event head，也不增加事件级损失：

- 保持现有代码兼容性；
- 在候选数不超过 $R$ 时将其视为直接透传；
- 论文机制和诊断重点放在节点级关系学习与 Top-K 聚合。

只有未来数据集的同日历候选数稳定大于 `event_top_r` 时，才有必要单独验证事件级粗排。当前不为尚未发生的问题增加结构。

## 7. 实施顺序

### 7.1 阶段 A：零训练诊断

- 增加仅用于 validation 诊断的 `level_weight=0` 配置或命令行覆盖；
- 对 source 和 random 各运行一次完整 retrieval diagnostic；
- 输出单独的正式 JSON，不覆盖现有 `level_weight=0.25` 结果；
- 根据第 3.3 节立即决定停止或进入 E4。

### 7.2 阶段 B：只有阶段 A 失败才实施

- 为数据索引增加 calendar-group sampler；
- 为 relation target 增加 weekday、slot 与单向因果 mask；
- 增加候选数、有效 anchor 数和时间边界单元测试；
- 先进行有限 batch 张量流验证，验证通过后立即删除 smoke 产物；
- 在 METR-LA 正式预训练一个 seed 42 E4 checkpoint；
- 先做 METR-LA validation 检索诊断；
- 通过同域门槛后才重建 PEMS-BAY Bank；
- 使用现有 target-random checkpoint 作为不训练对照；
- 先比较 PEMS-BAY retrieval，再运行一个 seed 42 horizon-only。

## 8. E4 成功与停止规则

E4 只有同时满足以下条件才保留：

1. METR-LA validation learned Top-K 不差于 E3 当前 3.732261；
2. PEMS-BAY learned Top-K future MAE 低于 target-random 的 2.173856；
3. PEMS-BAY horizon-only MAE 低于 target-random 的 1.878035；
4. seed 42 下游 MAE 相对 random 至少改善 0.5%，才值得进入多 seed；
5. RMSE、MAPE 不出现与 MAE 明显相反的系统退化。

若第 1 项失败，说明候选收缩损害源域学习，停止 E4。若第 1 项通过但第 2、3 项失败，则停止继续修改跨数据集 source pretraining，不再增加 E5 网络模块；后续将研究定位收缩为目标域自监督历史检索，或者采用 raw L1 作为确定性轻量检索基线。

## 9. Confidence 与后续边界

当前 confidence 在 PEMS-BAY source E3 上相对 horizon-only 有独立收益，因此不删除其实现。但阶段 A 或 E4 会改变 memory 排序，原 confidence checkpoint 随即失效。

正确顺序是：

1. 先确定最终 selector；
2. 再重新训练一次 confidence；
3. 只有 source encoder 明确优于 random，才运行多 seed；
4. validation 冻结最终方案后，才允许一次性读取 test。

在 selector 未通过 random 归因门槛前，不继续做 confidence 多 seed，也不读取 PEMS-BAY test。

## 10. 本方案的收敛性

本方案没有新增模型分支，只有两个连续决策：

- `level_weight=0` 解决“是分数组合问题还是 key 问题”；
- E4 候选对齐解决“预训练任务是否与部署检索空间一致”。

阶段 A 成功就不做 E4；E4 失败就停止继续扩展 source-transfer 结构。这样每个实验都关闭一个不确定性，并把工作推向保留、删除或转向，而不是继续发散。
