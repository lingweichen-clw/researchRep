# 跨数据集检索迁移验证实验计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变当前检索器、Bank schema 和下游校准器架构的前提下，验证 METR-LA 预训练检索编码器在 PEMS-BAY、PEMS04、PEMS07 和 PEMS08 上的迁移能力，并用最小成本决定哪些数据集进入下游校准实验。

**Architecture:** 采用漏斗式实验流程。阶段 0 只检查目标数据、图、归一化和物理变量契约；阶段 1 冻结源域 encoder，在每个目标域重新构建 Bank，只评估 learned、random、raw-L1 和 oracle 检索质量；只有检索阶段通过的数据集才进入目标域 Base-only 与 Router 下游验证。目标域 Bank 始终使用目标数据和目标图，不能直接复用 METR-LA Bank。

**Tech Stack:** Python 3.10、PyTorch、NumPy、pandas、HDF5/NPZ、现有 `stanchor` 数据、Bank 和 retrieval diagnostics 接口。

**Spec:** 当前 `doc/优化方案合集/2026-09-01-Retrieval-Aware-MHA-Residual-Router方案.md`、`stanchor/data/dataset.py`、`stanchor/bank/schema.py` 和 `stanchor/diagnostics/retrieval.py` 的数据与检索契约。

## Global Constraints

- 检索器输入保持 `[B,288,N,1]`，下游输入保持 `[B,12,N,1]`，预测 horizon 保持 12 步。
- 目标域 scaler 只能由目标域训练区间拟合；validation/test future 只能用于离线评价，不能用于 encoder、Bank 或 Router 更新。
- 源域 encoder 在阶段 1 全程冻结；encoder 参数改变后必须重新构建 Bank。
- Bank 必须记录并校验 encoder fingerprint、graph fingerprint、scaler、节点数、context length 和 schema version。
- 当前候选主协议为 `weekday_radius1_overlap`：查询时间槽的前一天、当天、后一天候选，并执行因果 future-end 过滤。
- 阶段 1 不训练下游 backbone 或 calibrator；不新增 relation loss、adapter 或端到端 Bank 更新。
- 任何 smoke 输出必须与正式结果分目录，并在验证后删除，不能写入论文结果表。

## 术语与证据边界

### 源域 encoder

源域 encoder 是在 METR-LA 上完成预训练的 HN-OffsetDecay v2 检索编码器。本计划默认 checkpoint 为 `artifacts/metrla_e5_tgge_hn_offset_decay_v2_transfer_hidden128_ffn2_b16_seed42/pretrain_best.pt`。阶段 1 中它只负责把目标域的 288 步历史窗口映射为 event key `[B,64]` 和 node key `[B,N,64]`，不使用目标域 future 更新参数。

### 目标域 Bank

目标域 Bank 是用目标数据集训练区间前 70% 的历史事件、目标域 scaler、目标域邻接图和冻结 source encoder 生成的只读事件库。每个事件保存 event key、node key、future、mask、时间索引和 level 特征。Bank 的 key 与 query key 必须由同一个 encoder 和同一套模型配置产生。

### 检索质量

检索质量表示历史候选 future 对目标 query future 的离线可用程度。对目标 query 的真实 future (Y\)，候选预测 \(\hat Y\) 的 MAE/RMSE/MAPE 只用于 validation/test 离线统计，不参与部署时的候选选择。Oracle Top-K 使用真实 future 选择候选，仅作为候选池上界，不能视为部署方法。

### 迁移类型

- **同物理变量迁移：** METR-LA speed → PEMS-BAY speed，以及 PEMS04/08 中确认后的 speed 通道。
- **跨物理变量迁移：** METR-LA speed → PEMS07 flow。PEMS07 结果单独报告，不与同变量主结果合并。

## 阶段 0：数据契约和质量审计

### 目标

在构建 Bank 前确认每个数据集可被当前窗口、scaler、图和检索接口正确解释。阶段 0 失败的数据集暂停，不进入阶段 1。

### 输入

| 数据集 | 原始文件 | 当前状态 |
|---|---|---|
| METR-LA | `data/METRLA_data/METR-LA.h5` | 源域参考 |
| PEMS-BAY | `data/pemsBay_data/pems-bay.h5`、`adj_mx_bay.pkl` | 目标域优先 |
| PEMS04 | `data/pems04_data/pems04.npz`、`distance.csv` | 3 通道，需确认 speed 通道 |
| PEMS07 | `data/PEMS07/PEMS07.npz`、`PEMS07.csv` | 单通道，单独跨变量分析 |
| PEMS08 | `data/PEMS08/PEMS08.npz`、`PEMS08.csv` | 3 通道，需确认 speed 通道 |

### 必查项目

1. 数据形状 `[T,N,C]`、dtype、有限值比例和零值比例。
2. 时间戳是否单调、是否重复、是否存在大于 5 分钟的跳跃。
3. 每节点和每通道的 min/max/mean/std，以及缺失率 q50/q95/max。
4. 训练/validation/test 按时间顺序切分，scaler 只拟合训练区间。
5. 图节点数与数据节点数一致，edge index 在 `[0,N)`，孤立节点数和度分布可接受。
6. `context_length=12`、`retrieval_context_length=288`、`horizon=12` 能在每个 split 生成有效窗口。
7. 多通道数据必须明确选择物理变量通道；未确认通道语义前不做正式迁移结论。

### 阶段 0 通过标准

- 所有用于正式实验的输入值有限，时间索引无重复；
- 图节点数、节点顺序和邻接矩阵一致；
- 训练区间至少能产生一个完整 Bank 事件和 validation query；
- speed 通道的数值范围和缺失率合理；
- PEMS07 若为 flow，明确标记为跨物理变量，不作为 speed-to-speed 主线。

### 产物

- `artifacts/cross_dataset_stage0/<dataset>_audit.json`
- `artifacts/cross_dataset_stage0/summary.json`

审计 JSON 必须记录：文件 fingerprint、形状、时间范围、缺失率、通道统计、图统计、split 边界、scaler 统计和 pass/fail 原因。

## 阶段 1：冻结 encoder 的目标域检索验证

### 固定设置

```yaml
retrieval_context_length: 288
context_length: 12
horizon: 12
candidate_protocol: weekday_radius1_overlap
event_top_r: 32
node_top_k: 12
level_weight: 0.0
key_dtype: float16
memory_fraction: 0.7
```

阶段 1 只改变目标数据集、目标图和目标 scaler；不改变 source encoder 的模型结构、checkpoint 或 retrieval fingerprint。

### Bank 构建

```text
目标域训练区间前 70% 的事件
→ source encoder.encode_clean（冻结）
→ 目标域 Bank
```

必须在 Bank manifest 中验证：

- `encoder_fingerprint` 与 source checkpoint 一致；
- `graph_fingerprint` 与目标域图一致；
- `scaler` 与目标域 query 数据一致；
- `num_nodes` 与目标域数据一致；
- `context_length=288`、`horizon=12`；
- `event_top_r=32` 不截断合法 calendar pool。

### 候选协议审计

对每个 query 统计 weekday offset `-1/0/+1` 的候选数量。不能只根据协议名称推断候选已扩展；如果当天或相邻天的 offset 长期为零，必须暂停并检查时间过滤。另统计 future 与 query 12 步 context 的重叠比例，并在报告中明确该协议允许重叠窗口。

### 检索方法

每个目标域 validation 只计算以下四种方法：

1. `source_learned_weighted_topk`：source encoder 的 node key + learned weighted Top-K。
2. `random_learned_weighted_topk`：随机初始化、结构相同 encoder 的 weighted Top-K 控制。
3. `raw_l1_topk`：query 短期 context 与候选 context 的逐节点 L1 Top-K。
4. `oracle_topk`：用真实 future 选择最优候选，仅作为上界。

weekly mean 不作为每个数据集的必做方法；如需要，仅在 PEMS-BAY 作为附加 sanity baseline。

### 阶段 1 指标

- learned/random/raw-L1/oracle 的 overall MAE、RMSE、MAPE；
- 15/30/60 分钟 horizon MAE；
- legal candidate pool 平均数、中位数和 q10/q90；
- node-level valid Top-K 数量和无候选率；
- Top-K oracle recall 与 Oracle gap；
- learned score 与真实 candidate error 的 Spearman 相关；
- candidate context/future overlap 比例；
- source 与 random 的相对差异。

### 阶段 1 Go/No-Go

数据集进入阶段 2 需要同时满足：

1. source encoder 不劣于 random encoder，优先要求相对改善至少 0.5%；
2. source weighted Top-K 不明显劣于 raw-L1，差距不超过 0.02 MAE；
3. candidate coverage ≥95%，无候选率 <5%；
4. `weekday_offset=-1/0/+1` 均有可解释的候选贡献，或对缺失 offset 给出数据边界解释；
5. Oracle Top-K 相对 Base-only 存在可利用空间；
6. 没有 Bank fingerprint、scaler、图节点或 future leakage 错误。

任一数据集未通过时，保留诊断 JSON 作为负结果，但不训练该数据集的 Router。

## 阶段 2：目标域下游验证（按需触发）

只有阶段 1 通过的数据集进入阶段 2。首批最多两个：PEMS-BAY，以及 PEMS04/PEMS08 中检索质量更好的一个。

每个数据集只训练：

```text
Target Base-only
Target Base + frozen source encoder + target Bank + Router
```

Target Base-only 必须在目标域重新训练；METR-LA Base checkpoint 不能作为目标域 baseline。两者使用相同的 split、scaler、backbone、seed、optimizer、scheduler、batch 和 stopping protocol。

Random Router 只在 source Router 相对 Base-only 改善小于 0.03 MAE 或结果方向异常时触发，训练 10–20 轮用于归因，不作为所有数据集的必做实验。

## 阶段 3：正式多种子结果

阶段 2 成功的数据集才补 `seed=123`，与 `seed=42` 报告 mean±std。测试集只在候选协议、Top-K、loss space、Bank 和 Router 配置全部锁定后使用。

## 结果解释规则

- source > random 且 Router > Base：支持“源域检索表示可迁移并可被校准器利用”。
- source > random 但 Router ≈ Base：检索器有效，问题在下游利用方式，不能判定检索失败。
- source ≈ random：迁移信号弱，先检查 scaler、通道、图和时间协议，不立即增加模块。
- source < random：暂停该数据集的下游实验，保留为负结果或转入轻量 adapter 研究。
- PEMS07 的 speed→flow 结果单独报告，不与 speed→speed 主结果合并。
