# E2 一天历史预训练与检索诊断报告

更新时间：2026-07-23

## 1. 诊断问题与结论

本报告回答两个问题：

1. 一天历史和扩大编码器能否正常完成预训练；
2. E2 得到的 node key 是否比旧版 12 步编码器更有检索价值。

核心结论如下。

1. **E2 训练正常收敛，没有出现无有效样本、损失不有限或检索监督坍缩。** 训练在第 39 轮早停，最佳综合验证损失位于第 29 轮。
2. **E2 明显改善了 learned retrieval。** learned weighted Top-K 的验证集 MAE 从旧版的 3.9047 降到 3.7600，改善 3.70%。
3. **改善主要来自候选集合，而不是仅靠聚合权重。** E2 的 learned uniform Top-K 已从 4.0998 降到 3.9531，并首次优于 raw-L1 Top-K；learned 权重在此基础上再带来约 0.1930 MAE 的收益，与旧版权重收益接近。
4. **E2 达到了本轮保留标准，但 selector 仍未接近上界。** learned Top-1 与 Oracle Top-1 仍相差 1.4918 MAE，因此当前结论是“保留 E2 并进入下游验证”，而不是“selector 已经解决”。
5. **本次诊断发现并修复了 E2 raw-L1 候选窗口错位。** 修复前 raw-L1 错误使用一天窗口开头的 12 步；修复后使用历史事件预测时刻前的最后 12 步。本文只使用修复后的完整诊断结果。

## 3. 损失函数及其含义

E2 沿用原预训练目标：

$$
\mathcal L_{\mathrm{total}}
=
\mathcal L_{\mathrm{mask}}
+\lambda_{\mathrm{ret}}\mathcal L_{\mathrm{ret}},
\qquad
\lambda_{\mathrm{ret}}=0.1.
$$

- $\mathcal L_{\mathrm{mask}}$：只在“原本有观测且被人工遮蔽”的位置计算 Smooth-L1 重建损失。
- $\mathcal L_{\mathrm{ret}}$：future-guided retrieval loss。它推动 future 相似的同节点 key 靠近，并提高“context 相似但 future 不相似”的时空海市蜃楼负样本权重。
- 两个损失都在模型归一化空间计算，不是实际速度单位，不能与下游 MAE 直接比较。

检索 key 张量为：

$$
\mathbf K\in\mathbb R^{B\times N\times D_r}
=
\mathbb R^{16\times207\times48},
$$

其中 $B$ 是 batch size，$N$ 是传感器节点数，$D_r$ 是 node key 维度。

从 epoch 1 到最佳 checkpoint：

- validation mask 下降 25.28%；

重建任务收敛明确。检索损失在前 10 到 13 轮下降较快，之后主要在 1.26 到 1.29 之间波动；训练检索损失继续下降到 1.1846，而验证检索损失进入平台期，表现为轻度泛化间隔，不是训练失败。

### 4.2 checkpoint 选择的边界

当前 checkpoint 按 $\mathcal L_{\mathrm{total}}$ 保存，因此选择了 epoch 29，而不是检索损失最低的 epoch 31。epoch 29 中检索项对综合验证损失的贡献约为：

$$
\frac{0.1\times1.278666}{0.342755}\times100\%
=37.31\%.
$$

这说明综合目标并非完全由重建支配，但“最佳综合预训练模型”不一定等于“最佳检索模型”。后续训练代码应同时保存 `best_total` 和 `best_retrieval`，再用完整 retrieval diagnostics 决定用于 Bank 的 checkpoint；这只增加 checkpoint 选择证据，不改变模型结构。

### 4.3 检索监督是否充足

完整 batch 理论上最多有：

$$
B\times N=16\times207=3312
$$

个节点级 anchor。epoch 29 的统计为：

| 指标 | train | validation |
|---|---:|---:|
| 平均有效 anchor / batch | 3266.27 | 3251.14 |
| 理论 anchor 覆盖率 | 98.62% | 98.16% |
| positive pairs / anchor | 1.998 | 1.859 |
| hard negatives / anchor | 0.413 | 0.478 |
| skipped batches | 0 | 0 |

因此 E2 并不存在“每个 anchor 只有一个候选导致无法学习”的问题。日志中的 anchor、positive 和 hard-negative 数量主要由 batch 采样、缺失掩码及分位数规则决定，不是模型预测值；validation 使用固定顺序，所以这些计数跨 epoch 不变是正常现象。

## 5. 修正后的检索价值诊断

### 5.1 指标定义

对真实未来 $\mathbf Y$ 和历史聚合结果 $\widehat{\mathbf Y}$，在所有方法共同有效的位置集合 $\Omega$ 上计算：

$$
\operatorname{MAE}(\widehat{\mathbf Y},\mathbf Y)
=
\frac{1}{|\Omega|}
\sum_{i\in\Omega}
\left|\widehat Y_i-Y_i\right|.
$$

该 MAE 已逆标准化到 METR-LA 的实际速度尺度，越低越好。

- `raw-L1 Top-K`：按最近 12 步原始标准化窗口的节点级 L1 距离选取 $K=5$ 个历史事件，然后均匀聚合 future。
- `learned uniform Top-K`：使用 learned key 选择 $K=5$，但均匀聚合，用于隔离“候选选择”的贡献。
- `learned weighted Top-K`：使用 learned key 选择，并使用 learned score 的 softmax 权重聚合。
- `Oracle Top-1`：偷看真实 future 后，从同一合法候选池中选择节点级误差最小的事件，只表示不可部署上界。

### 5.2 E2 内部对照

| 方法 | MAE | 相对 weekly mean 增益 |
|---|---:|---:|
| weekly mean | 4.3781 | 0.00% |
| raw-L1 Top-1 | 4.3182 | +1.37% |
| raw-L1 Top-K | 3.9892 | +8.88% |
| learned Top-1 | 4.2631 | +2.63% |
| learned uniform Top-K | 3.9531 | +9.71% |
| **learned weighted Top-K** | **3.7600** | **+14.12%** |
| Oracle Top-1 | 2.7713 | +36.70% |

可以得到三条归因结论：

1. learned Top-1 比 raw-L1 Top-1 低 0.0551，说明 E2 key 的第一名排序已具有正贡献。
2. learned uniform Top-K 比 raw-L1 Top-K 低 0.0362，说明 E2 选择的候选集合整体优于无参数 L1 候选集合。
3. learned weighted Top-K 比 learned uniform Top-K 再低 0.1930，说明权重仍有效；但该收益与旧版的 0.1951 基本相同，因此 **E2 的新增收益主要来自候选选择改善，而不是权重机制变强**。

learned weighted Top-K 相对 raw-L1 Top-K 的改善为：

$$
\frac{3.9892-3.7600}{3.9892}\times100\%
=5.75\%.
$$

这比旧版 learned 相对 raw-L1 的 2.35% 优势更明确。

### 5.3 与旧版编码器的比较

| 方法 | 旧版 MAE | E2 MAE | E2 相对改善 |
|---|---:|---:|---:|
| weekly mean | 4.3729 | 4.3781 | -0.12% |
| raw-L1 Top-1 | 4.3493 | 4.3182 | +0.72% |
| raw-L1 Top-K | 3.9986 | 3.9892 | +0.24% |
| learned Top-1 | 4.4368 | 4.2631 | **+3.92%** |
| learned uniform Top-K | 4.0998 | 3.9531 | **+3.58%** |
| learned weighted Top-K | 3.9047 | 3.7600 | **+3.70%** |
| Oracle Top-1 | 2.7977 | 2.7713 | +0.94% |

weekly、raw-L1 和 Oracle 的变化均小于 1%，说明两个评估子集难度接近；三个 learned 方法则一致改善约 3.6% 到 3.9%。因此改善不能仅由 E2 validation 少了边界 query 来解释，主要证据仍指向 learned representation 变好。

### 5.4 Oracle 差距和权重分布

| 指标 | 旧版 | E2 |
|---|---:|---:|
| learned Top-1 - Oracle Top-1 | 1.6391 | 1.4918 |
| top-1 weight 均值 | 0.3800 | 0.3972 |
| 有效支持数 $K_{\mathrm{eff}}$ | 3.8750 | 3.7465 |

Oracle 差距缩小 8.99%，但 1.4918 MAE 仍然很大。E2 权重略微集中，同时 $K_{\mathrm{eff}}$ 仍接近 4，说明没有退化成单候选。当前 selector 已从“第一名不可靠”改善为“第一名略优于 raw-L1”，但仍只利用了候选池潜力的一小部分。

## 6. 诊断中发现的 raw-L1 错位

E2 Bank 的：

- `context_start` 是 288 步 retrieval window 的起点；
- `context_end` 是预测前最后一个历史时刻；
- raw-L1 对照应使用历史事件最后 12 步，即从 `context_end - 11` 到 `context_end`。

原实现错误地从 `context_start` 读取 12 步，相当于拿“一天窗口最早的一小时”与 query 的“最近一小时”比较。修复后候选起点为：

$$
t^{\mathrm{pred-start}}_r
=
t^{\mathrm{context-end}}_r-T_{\mathrm{pred}}+1.
$$

其中 $T_{\mathrm{pred}}=12$。该修复不改变 learned retrieval、weekly mean、Oracle、checkpoint 或 Bank 内容，只修正 raw-L1 对照和未来 E2 raw-L1 下游实验的窗口语义。

## 7. 最终判断与下一步

### 7.1 保留或删除决策

**保留 E2。** 它满足原调整方案中的四个核心验收条件：

1. learned Top-1 优于旧版，并优于当前 raw-L1 Top-1；
2. learned uniform Top-K 已超过 raw-L1 Top-K；
3. learned weighted Top-K 优于旧版 3.9047；
4. learned Top-1 与 Oracle 的差距缩小。

当前不加入 ST-Norm、FFT 或额外 selector 网络。E2 已验证“更长上下文和更充分编码容量”能够修复一部分表示不足，继续堆结构会重新混淆归因。

### 7.2 下一项科学实验

下一步只验证一个问题：

> E2 检索 MAE 的改善，能否转化为下游预测改善？

在相同下游 backbone 和 seed 下比较：

1. `raw_l1_topk_horizon`；
2. `learned_topk_horizon`；
3. `learned_topk_confidence`。

若 E2 learned 模式不能稳定优于修正后的 raw-L1 模式，则停止继续增强 encoder；若能够稳定改善，再补 E1“12 步输入 + 同参数量编码器”以区分长历史和参数量的贡献。
