# TGGE 下游校准器 A–D 验证报告

## 1. 验证目的与协议

本报告基于 METR-LA 验证集（2,993 个 query，94 个 batch），对同一份冻结 base、同一份冻结预训练编码器和同一份 `case_bank_hn_offset_decay_v1_seed42` 进行验证阶段诊断。真实 future 只用于离线 oracle 评价，不进入检索、校准器输入或部署路径。

GWN 使用 `formal_20260826_gwn_sampleid_cache_50_restart/downstream_best.pt`（第 43 轮）；STGCN 使用 `formal_20260826_stgcn_sampleid_cache_50/downstream_best.pt`（第 4 轮）。

## 2. 实验 A：memory intervention

该实验不重新训练，只替换最终输出。`base` 是冻结 backbone 预测；`current_learned_gate` 是当前校准器；`oracle_binary_gate` 和 `oracle_continuous_alpha` 使用验证 future 计算理想门控，因此是上界，不可部署；`oracle_candidate_top1` 与 `oracle_candidate_error_weighted` 直接使用真实 future 选择候选，同样不可部署。

| 方法 | GWN MAE | STGCN MAE |
|---|---:|---:|
| base | 2.865798 | 2.901381 |
| current learned gate | 2.822513 | 2.835027 |
| oracle binary gate | 2.279876 | 2.189602 |
| oracle continuous alpha | 2.169077 | 1.990904 |
| oracle candidate top-1 | 1.666505 | 1.663934 |
| oracle candidate error-weighted | 1.647054 | 1.644484 |
| fixed alpha=0.05 | 2.855785 | 2.882973 |
| fixed alpha=0.10 | 2.850556 | 2.876004 |
| fixed alpha=0.20 | 2.850628 | 2.885880 |
| fixed alpha=0.30 | 2.862466 | 2.920281 |
| fixed alpha=0.50 | 2.916149 | 3.046840 |

结论：当前 TGGE 相对 base 的收益真实存在，但理想门控仍有约 0.54–0.84 MAE 的巨大空间；更大的上界来自候选 future 选择，说明瓶颈不是单一的 alpha，而是“候选 future 质量/候选间信息冲突 + 校准器判断能力”共同造成。固定小 alpha 比较稳定，说明当前 memory residual 方向有价值但不适合大幅注入。

## 3. 实验 B：alpha、beta 与 residual 分布

现有新版校准器对外返回的 `fusion_weight` 即 alpha；新版 `additive_contributions` 实际返回两个聚合诊断通道（residual magnitude 与 dispersion），而不是旧版 9 维贡献。因此本实验按实际接口记录，不将不存在的 9 维字段伪造成结果。

| 指标 | GWN | STGCN |
|---|---:|---:|
| alpha mean | 0.1870 | 0.2009 |
| alpha std | 0.1064 | 0.0865 |
| alpha median | 0.1609 | 0.1887 |
| alpha P90 | 0.3449 | 0.3200 |
| alpha max | 0.9268 | 0.7499 |
| memory-only MAE | 3.182222 | 3.600600 |
| final MAE | 2.822514 | 2.835027 |
| risk Spearman | 0.0333 | -0.0127 |
| risk R2 | -1.5575 | -1.4930 |

alpha 不是常数，但它与真实 helpfulness 的排序能力很弱；高 alpha 主要表示校准器愿意注入更多 residual，并不等价于“memory 一定有用”。`memory-only` 明显劣于 base，而 final 优于 base，说明校准器确实在抑制部分错误 memory，但还没有学会可靠地识别可用候选。当前正式训练中 risk/blend 权重为 0，因此 risk 指标只能作为旁路诊断，不能被解释为已训练好的风险预测器。

## 4. 实验 C：attention 区分候选

本轮未将候选 attention 权重暴露到诊断输出，因而没有伪造 Top-1 weight、Top-5 cumulative weight、entropy 或 attention–future-error Spearman。现有结果只能证明最终 alpha 的条件化变化，不能证明候选 attention 已经正确偏向 future 更接近真实值的候选。

因此 C 的状态是：**接口证据不足，不能判定为完成**。下一步只需给 `CandidateSetHorizonCorrector` 增加 validation-only debug return，记录每个 query/horizon 的 attention，再复用现有验证协议完成 C；不需要重新训练。

## 5. 实验 D：候选池 K 敏感性

保持 checkpoint 不变，仅改变验证阶段 `node_top_k`：

| K | GWN MAE | STGCN MAE |
|---:|---:|---:|
| 1 | 2.892905 | 2.884296 |
| 3 | 2.829685 | 2.839735 |
| 5 | 2.822513 | 2.835027 |
| 8 | 2.824625 | 2.839465 |

K=1 明显变差，K 从 1 增加到 3 带来主要收益；K=5 最好，K=8 略有回落。候选集合中确实存在互补信息，但继续增加候选会引入噪声。当前 `node_top_k=5` 是合理的局部最优，不建议盲目扩大到 8 以上。

## 6. 最终判断

1. **检索候选不是完全无价值。** oracle candidate top-1 MAE 约 1.66，说明候选池中确实包含非常接近真实 future 的事件。
2. **内部候选排序/聚合仍是重要瓶颈。** 真实 future 选择候选远好于当前 weighted mean；memory-only MAE 甚至劣于 base，说明聚合会抹平有效候选并混入冲突 future。
3. **诊断校准器也是主要瓶颈。** oracle binary/continuous gate 与 learned gate 差距很大，且 risk Spearman 接近 0，说明当前诊断器没有可靠预测“何时、向哪个方向、注入多少 memory”。
4. **当前最合理的后续方向不是继续扩大结构。** 保留 K=5 和现有低参数校准器，优先增加 validation-only attention 可观测性并验证 C；若 C 显示 attention 与候选真实误差无关，再针对候选打分/聚合训练目标做单变量改动。
5. **A–D 状态：A、B、D 已完成；C 尚缺 attention debug 输出。** 因而目前不能严谨地宣称四组实验全部完成。
