# 检索学习诊断报告

## 1. 诊断目的

本报告只回答一个问题：

> 预训练得到的历史块检索，是否比同周时间槽均值和无参数原始窗口检索更有预测价值？

本次不训练下游模型，不修改 encoder，不增加新模块。所有方法使用同一个 METR-LA 验证集、同一个完整历史 Bank 和同一组有效预测位置。

## 2. 实验对象

| 项目 | 设置 |
|---|---|
| 数据集 | METR-LA |
| 评估划分 | validation，3240 个 query |
| 输入与预测长度 | $T=12,\ H=12$ |
| Bank | 训练窗口前 70%，共 15971 个历史事件 |
| checkpoint | patch3 预训练 epoch 18 |
| 日历过滤 | 相同 context-end `weekday-slot` |
| 因果过滤 | 候选 `future_end` 早于 query `context_start` |
| 共同评估覆盖率 | 95.05% |

共同评估覆盖率表示七类方法都能给出预测、且真实 future 有观测的元素比例。下文所有 MAE 都在完全相同的共同位置上计算，避免缺失率不同造成不公平比较。

## 3. 统一符号

- $B$：query 数量，本次为 3240。
- $H$：预测步数，本次为 12。
- $N$：节点数，本次为 207。
- $C$：预测通道数，本次为 1，即速度。
- $R_b$：query $b$ 经过日历与因果过滤后的候选事件数。
- $K$：每个节点保留的候选数，本次为 5。
- $Y_{b,h,n,c}$：query 的真实未来，形状为 $B\times H\times N\times C$。
- $F_{b,h,n,r,c}$：第 $r$ 个历史候选的真实 future，形状为 $B\times H\times N\times R\times C$。
- $M_{b,h,n,r,c}\in\{0,1\}$：候选 future 是否有有效观测。
- $w_{b,n,k}$：节点 $n$ 对第 $k$ 个候选的聚合权重，且有效权重之和为 1。

## 4. 指标与计算方法

### 4.1 Retrieved Future MAE

对于任意历史检索方法，先得到预测 $\widehat Y$，再逆标准化到真实速度尺度。MAE 为：

\[
\operatorname{MAE}(\widehat Y,Y)
=
\frac{1}{|\Omega|}
\sum_{(b,h,n,c)\in\Omega}
\left|\widehat Y_{b,h,n,c}-Y_{b,h,n,c}\right|.
\]

$\Omega$ 是所有方法共同有效的预测位置集合。该指标单位与 METR-LA 速度单位一致；越小表示历史信息对真实未来的直接预测越准确。

### 4.2 Weekly Mean

`weekly_mean` 对同一 `weekday-slot` 的全部合法历史 future 做均值：

\[
\widehat Y^{\mathrm{mean}}_{b,h,n,c}
=
\frac{
\sum_{r=1}^{R_b}M_{b,h,n,r,c}F_{b,h,n,r,c}
}{
\sum_{r=1}^{R_b}M_{b,h,n,r,c}
}.
\]

它表示稳定的周期历史基准。这里评估的是周期均值的非参数 future 预测能力，不等同于完整 ST-SSDL 模型。

### 4.3 Raw-L1 检索

设 $\widetilde X^q_{b,t,n,c}$ 和 $\widetilde X^r_{b,t,n,c}$ 分别为经过训练集 scaler 标准化的 query context 与候选 context。节点级原始距离为：

\[
d^{\mathrm{raw}}_{b,n,r}
=
\frac{1}{|\Omega^X_{b,n,r}|}
\sum_{(t,c)\in\Omega^X_{b,n,r}}
\left|
\widetilde X^q_{b,t,n,c}
-
\widetilde X^r_{b,t,n,c}
\right|.
\]

$\Omega^X_{b,n,r}$ 是两个 context 在该节点上共同有观测的位置。`raw_l1_top1` 选择距离最小的一个候选；`raw_l1_topk` 选择距离最小的五个候选并做均匀平均。它们都不使用神经网络检索 key。

### 4.4 Learned 检索分数与聚合

学习检索首先计算节点 key 的余弦相似度，再加入水平匹配奖励：

\[
s_{b,n,r}
=
(z^q_{b,n})^\top z^r_{b,n}
+
\lambda_{\mathrm{level}}
\exp\left(
-\frac{d^{\mathrm{level}}_{b,n,r}}{\tau_{\mathrm{level}}}
\right).
\]

$z^q,z^r\in\mathbb R^{32}$ 是 L2 归一化 node key；$d^{\mathrm{level}}$ 是均值、标准差、末值和首末差的平均绝对距离。本次 $\lambda_{\mathrm{level}}=0.25$，$\tau_{\mathrm{level}}=1$。

top-K 权重为：

\[
w_{b,n,k}
=
\frac{
\exp(s_{b,n,k}/\tau_{\mathrm{search}})
}{
\sum_{j=1}^{K}\exp(s_{b,n,j}/\tau_{\mathrm{search}})
},
\qquad \tau_{\mathrm{search}}=0.1.
\]

加权历史预测为：

\[
\widehat Y^{\mathrm{learned}}_{b,h,n,c}
=
\frac{
\sum_{k=1}^{K}w_{b,n,k}M_{b,h,n,k,c}F_{b,h,n,k,c}
}{
\sum_{k=1}^{K}w_{b,n,k}M_{b,h,n,k,c}
}.
\]

`learned_top1` 只使用最高分候选；`learned_uniform_topk` 保留 learned 选出的五个候选但改为均匀权重；`learned_topk` 同时使用 learned 候选和 learned 权重。

### 4.5 Oracle Top-1

Oracle 在同一个合法候选池内，偷看 query 的真实 future，并为每个节点选择 future MAE 最小的单个历史事件：

\[
r^*_{b,n}
=
\arg\min_{1\le r\le R_b}
\frac{1}{|\Omega^Y_{b,n,r}|}
\sum_{(h,c)\in\Omega^Y_{b,n,r}}
\left|F_{b,h,n,r,c}-Y_{b,h,n,c}\right|.
\]

Oracle 不能部署。它只表示“同一候选池中最佳单事件”能够达到的结果，用于区分候选池不足和 selector 选择失败。

Oracle 与 learned top-1 的差距定义为：

\[
\Delta_{\mathrm{selector}}
=
\operatorname{MAE}_{\mathrm{learned\ top1}}
-
\operatorname{MAE}_{\mathrm{oracle\ top1}}.
\]

$\Delta_{\mathrm{selector}}>0$ 表示候选池中存在更好的历史事件，但 learned selector 没有选中。

### 4.6 相对 Weekly Mean 增益

\[
\operatorname{Gain}_{\%}
=
\frac{
\operatorname{MAE}_{\mathrm{weekly}}
-
\operatorname{MAE}_{\mathrm{method}}
}{
\operatorname{MAE}_{\mathrm{weekly}}
}
\times100\%.
\]

增益为正表示优于周期均值，增益为负表示比周期均值更差。

### 4.7 Top-1 Weight 与有效支持数

`top1 weight` 是五个 learned 权重中的最大值：

\[
w^{\mathrm{top1}}_{b,n}=\max_{1\le k\le K}w_{b,n,k}.
\]

有效支持数定义为：

\[
K_{\mathrm{eff}}(b,n)
=
\frac{1}{\sum_{k=1}^{K}w_{b,n,k}^{2}}.
\]

当 $K=5$ 时，$K_{\mathrm{eff}}=1$ 表示退化为单候选；$K_{\mathrm{eff}}=5$ 表示五个候选权重完全均匀。

## 5. 主要结果

| 方法 | MAE | 相对周期均值增益 | 解释 |
|---|---:|---:|---|
| weekly mean | 4.3729 | 0.00% | 周期历史基准 |
| raw L1 top-1 | 4.3493 | +0.54% | 单候选原始距离几乎没有优势 |
| raw L1 top-K | 3.9986 | +8.56% | 无参数多候选平均已经有效 |
| learned top-1 | 4.4368 | -1.46% | 学习排序的第一名不可靠 |
| learned uniform top-K | 4.0998 | +6.24% | learned 选出的候选集合不如 raw L1 集合 |
| **learned weighted top-K** | **3.9047** | **+10.71%** | 最佳可部署历史检索方法 |
| oracle top-1 | 2.7977 | +36.02% | 候选池存在很大理论空间 |

补充比较：

- learned weighted top-K 比 raw L1 top-K 的 MAE 低 0.0939，相对改善约 2.35%。
- learned 权重比同一候选集合的均匀权重低 0.1951，相对改善约 4.76%。
- learned top-1 与 Oracle top-1 的 MAE 差为 1.6391，说明单事件排序仍然较弱。

## 6. 候选数量与权重诊断

| 指标 | 均值 | q10 | 中位数 | q90 | 范围 |
|---|---:|---:|---:|---:|---:|
| 原始合法事件数 | 8.06 | 7.00 | 8.00 | 9.00 | 5-9 |
| 节点有效 top-K 数 | 5.00 | 5.00 | 5.00 | 5.00 | 5-5 |
| top-1 weight | 0.380 | 0.254 | 0.341 | 0.557 | 0.201-1.000 |
| $K_{\mathrm{eff}}$ | 3.875 | 2.519 | 4.121 | 4.811 | 1.000-5.000 |

因此，完整 Bank 中不存在“每个节点平均只有一个候选”的问题。大多数节点同时使用约 4 个候选，整体没有发生 top-1 权重坍缩；只有少数样本接近单候选。

## 7. 结论

1. **历史候选池有价值。** Oracle top-1 比周期均值低 36.02%，说明相同周时间槽的不同历史周并非完全同质。
2. **单事件 selector 没学好。** learned top-1 比周期均值差 1.46%，也不如 raw L1 top-1。
3. **多候选聚合是当前真正有效的部分。** raw L1 top-K 已比周期均值好 8.56%，说明降方差本身贡献很大。
4. **learned 权重有额外但有限的价值。** learned weighted top-K 比 raw L1 top-K 再改善约 2.35%，证明学习表示不是完全无效，但收益没有大到支持继续堆叠复杂 selector。
5. **事件级粗检索当前冗余。** 每个日历桶最多只有 9 个合法事件，小于 `event_top_r=32`；事件 top-R 不会删除任何候选，最终选择实际由节点级精排完成。

## 8. 收敛决策与下一步

当前不修改 encoder，不增加损失，不扩大候选池，也不继续 patch1 分支。

下一步只做一组下游对照，在相同轻量 backbone 下比较：

1. `base only`；
2. `base + weekly mean`；
3. `base + raw L1 top-K`；
4. `base + learned weighted top-K`。

若 learned weighted top-K 不能稳定优于 raw L1 top-K，则删除预训练 selector，保留更简单的无参数多历史块聚合；若能够稳定提高下游预测，再保留节点 key 与 learned 权重。事件级 coarse retrieval 已被证明在当前候选规模下是无效步骤，最终版本应删除，但在下游价值确认前不做破坏 checkpoint/Bank 契约的重构。

本报告来自单数据集、单 seed 的 validation 诊断，只用于机制去留，不作为最终论文结果。
