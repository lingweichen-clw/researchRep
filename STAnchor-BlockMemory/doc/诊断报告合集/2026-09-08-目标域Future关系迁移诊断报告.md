# 目标域 Future 关系迁移诊断报告（HN-OffsetDecay v2）

## 1. 报告目的与结论先行

本报告独立汇总 PEMS-BAY、PEMS04 和 PEMS08 上的检索表示迁移 CaseStudy。读者不需要回看 METR-LA 源域报告即可理解实验设置、指标和结果。

本实验回答两个问题：

1. 在目标域中，METR-LA 预训练得到的检索编码器是否仍然能把 **future 关系相近** 的事件排在一起？
2. 在目标域进行 T1 head-adapter 微调后，这种 future-relation 对齐是否进一步改善？

主要结论如下：

- `source` 在三个目标域的两种候选协议下均优于 `random`，但增益大小取决于协议和数据集；
- `finetuned` 在六组实验中均优于对应的 `source`，说明目标域微调确实进一步改善了 future-relation 对齐；
- `broad_causal` 候选池固定为 96，检验的是较宽候选池中的全局检索能力；
- `weekday_radius1_overlap` 是当前正式下游协议，候选池受时间日历限制，PEMS04/08 约 12 个，PEMS-BAY 约 38 个，因此其绝对指标不能直接与 broad-causal 的绝对值横向等同；
- PEMS08 的 weekday 受限协议中，`source` 的 global Spearman 相对 `random` 几乎持平，但局部排序和 Recall/NDCG 仍为正，且微调后所有指标继续改善。这说明迁移不是“所有统计量都同步大幅提升”，而是具有数据集和协议敏感性；
- CaseStudy 证明的是 **key 空间与 future teacher 距离的关系**，不能单独等同于最终下游预测 MAE 的必然改善。

## 2. 实验对象与统一比较原则

### 2.1 数据集与验证范围

实验在三个目标域的完整 validation split 上进行：

| 数据集 | 查询数 | 验证 batch 数 | 节点数（由数据集决定） |
|---|---:|---:|---:|
| PEMS04-speed | 1,400 | 175（broad）/ 88（weekday） | 307 |
| PEMS08-speed | 1,486 | 186 | 170 |
| PEMS-BAY | 4,912 | 614 | 325 |

查询数和节点数共同决定 anchor 数量。一个 anchor 指定一个 `(query event, node)`，因此 PEMS04 的 anchor 数为 `1,400 × 307 = 429,800`，PEMS08 为 `1,486 × 170 = 252,620`，PEMS-BAY 为 `4,912 × 325 = 1,596,400`。

### 2.2 三种 selector

三种方法使用完全相同的 query、候选事件 ID、future payload 和有效性 mask，唯一变化是用于计算 key distance 的表示：

1. **random**：随机初始化的目标域检索编码器表示，作为无语义学习控制；
2. **source**：METR-LA 上预训练的 HN-OffsetDecay v2 编码器直接迁移到目标域，不使用目标域 future 更新参数；
3. **finetuned**：在目标域上完成 T1 head-adapter 微调后的编码器表示。

这里的 `source` 与 `finetuned` 都是检索编码器实验，不是下游校准器实验。T1 微调只更新预先规定的适配分支，主干保持冻结，具体 checkpoint 和 Bank 已写入对应 JSON 的审计字段。

### 2.3 候选协议

#### `broad_causal`

候选必须满足：候选 future 已在 query context 开始之前结束，即不使用 query 时刻之后的信息。候选池先按事件时间轴构造，再固定抽取最多 `event_top_r=96` 个事件。该协议用于观察较宽候选池中 key 对 future 关系的排序能力。

#### `weekday_radius1_overlap`

这是当前正式下游协议。对 query 的 weekday 和 slot，收集：

- 前一天同一 slot；
- 当天同一 slot；
- 后一天同一 slot。

该协议允许候选 context 与 query context 重叠，但要求候选 future 在 query context 结束前已经结束。候选数量取决于数据集历史覆盖长度：

| 数据集 | 平均候选数 | 最小–最大 |
|---|---:|---:|
| PEMS04 | 12.074 | 12–13 |
| PEMS08 | 12.400 | 12–14 |
| PEMS-BAY | 37.861 | 35–39 |

PEMS04 的约 12 个候选是正常现象：其 Bank 每个 weekday-slot 平均约有 4 个历史事件，前一天、当天、后一天合计约 `4 × 3 = 12`。这不是把候选错误地限制成三条事件，也不是误用了 exact-calendar。

## 3. HN-OffsetDecay v2 teacher 距离

### 3.1 Future signature

每个事件的 future 为 12 步序列 (Y_{h,n})，其中 (h=1,ldots,H)，(n) 为节点。先取该事件 context 中每个节点最后一个有效观测值 (e_n)。如果最后一步缺失，则退化为 context 可见值的均值。

构造 OffsetDecay future signature：

\[
\phi_{h,n}=Y_{h,n}-\lambda_h e_n,
\qquad
\lambda_h=1-\frac{h-1}{H-1}.
\]

因此近端 horizon 去除更多当前 level，远端 horizon 的校正逐渐衰减到 0。它强调事件未来的演变关系，同时降低不同事件绝对速度/流量水平差异造成的干扰。

### 3.2 Future distance

对 query 与候选事件，在共同有效的 horizon、节点和通道上计算 masked MAE，得到原始 future distance。随后采用 `symmetric_geometric_mean` 做尺度归一化：query 和 candidate 各自的局部距离尺度共同参与归一化，避免某个事件整体幅值较大而主导距离。

记归一化后的 teacher 距离为：

\[
d^{future}_{q,n,r},
\]

其中 (q) 是 query，(n) 是节点，(r) 是候选事件。距离越小，表示两个事件在 HN-OffsetDecay future 演变上越相近。

### 3.3 Key distance

检索编码器输出 query key (z^q_{q,n}) 和候选 key (z^c_{q,r,n})。CaseStudy 使用 cosine distance：

\[
d^{key}_{q,n,r}=1-\cos(z^q_{q,n},z^c_{q,r,n}).
\]

如果编码器学到了有用的 future relation，则较小的 key distance 应总体对应较小的 future distance。因此 Spearman、Kendall 等指标应为正，并且越大越好。

Future 只用于 validation 后的 teacher 诊断：不参与 query key、candidate key、候选池构造或部署期排序，因而不存在把真实 future 泄漏进检索表示的情况。

## 4. 指标定义与解释

### 4.1 Global Spearman

把所有有效的 ((q,n,r)) pair 展平，对 (d^{key}) 和 (d^{future}) 计算 Spearman 秩相关：

\[
\rho_{global}=\operatorname{Spearman}(d^{key},d^{future}).
\]

它衡量全体 pair 的整体单调关系，适合观察 key 空间是否总体反映 future 相似性，但会受到样本量大、不同 anchor 分布差异的影响。

### 4.2 Anchor-wise Spearman

固定一个 `(query, node)`，只在其候选轴 (r) 内计算 Spearman，再对有效 anchor 求平均：

\[
\bar\rho_{anchor}=\frac{1}{|\mathcal A|}
\sum_{a\in\mathcal A}\rho_a.
\]

它回答“对一个具体节点和 query，候选排序是否正确”，比 global Spearman 更接近实际 Top-K 检索行为。少于两个有效候选的 anchor 不计入该项。

### 4.3 Anchor-wise Kendall

在每个 anchor 内比较候选 pair 的顺序一致性，再取均值。Kendall 对局部次序交换更敏感，作为 Anchor-wise Spearman 的补充。

### 4.4 Recall@1、NDCG@5、Recall@5

- **Recall@1**：key distance 最小的候选是否也是 future distance 最小的候选；
- **Recall@5**：key Top-5 与 future Top-5 的重叠比例；
- **NDCG@5**：按 future distance 产生连续相关性，再评价 key Top-5 的排序质量，越接近 1 越好。

这些指标直接描述 Top-K 候选选择质量。

### 4.5 Future-neighbor Recall@5

该指标与 Recall@5 使用相同的 key Top-5 和 future Top-5，但采用候选集合交集比例，并要求有效候选数大于 5 才计入。它强调 key 选出的邻居是否覆盖 future teacher 定义的近邻集合。

在当前实现中，`future_neighbor_recall_at_5` 与 Anchor-wise `Recall@5` 使用相同的 Top-5 集合交集定义，因此本报告中的数值通常相同。前者由张量化 future-neighbor 统计路径计算，后者由 anchor-wise 排序统计路径计算；两者同时保留是为了分别审计候选邻居覆盖和局部排序结果，而不是把它们当作两个独立的精度来源。

### 4.6 差值定义

报告同时给出：

\[
\Delta_{source-random}=M(source)-M(random),
\]

\[
\Delta_{finetuned-source}=M(finetuned)-M(source).
\]

对于所有相关指标，正值表示后者在该指标上更好。差值比单独看绝对值更适合跨数据集判断迁移是否稳定。

## 9. 结果含义与边界

### 9.1 可以支持的科研结论

1. **源域预训练具有可迁移的 future-relation 结构。** 三个目标域、两种协议中 source 均超过 random，且不依赖单一指标。
2. **目标域 T1 微调能够进一步适配当地分布。** finetuned 在全部六组实验中改善 source 的 global、局部排序和 Top-K 指标。
3. **候选协议会影响可观测增益。** broad-causal 候选更宽，能够更充分检验表示空间；weekday 受限协议更接近部署，绝对指标和增益会因候选构成不同而变化。
4. **局部排序指标对实际检索更重要。** 当 global Spearman 在 PEMS08 weekday 中几乎不变时，anchor-wise 和 Top-K 指标仍能显示局部选择质量的改善。

### 9.2 不能过度宣称的内容

- 不能仅凭 CaseStudy 宣称 source 在所有数据集上具有相同幅度的提升；
- 不能把 PEMS04/PEMS08 的 12 候选与 PEMS-BAY 的 38 候选的绝对 Recall 直接比较优劣；
- 不能把 key-future 距离对齐直接等同于下游预测 MAE 必然下降；
- 不能把 validation teacher 指标解释为部署期使用了真实 future。真实 future 仅用于离线评价，部署期候选选择仍只使用 context、Bank 和 key。
