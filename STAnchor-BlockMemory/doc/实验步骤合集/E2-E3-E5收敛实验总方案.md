## 1. 本轮要解决的三个问题

当前工作量已经足够，问题不再是“还能加入什么模块”，而是已有实验较分散，论文证据链尚未完全闭合。本轮只回答三个问题：

1. **预训练是否真的有用？** 对 E2、E3、E5A 分别补齐同构 random 对照，区分预训练收益和随机检索结构收益。
2. **selector 是否学到了预期的 future relation？** 通过统一的离线可视化和数值诊断，检查预训练模型检索出的历史事件是否比 random 更接近 query 的真实未来。
3. **memory 是否能接入不同下游模型？** 在当前轻量下游和 ST-SSDL 两个宿主上使用相同 memory 接口，验证收益是否具有模型无关性。

严格执行顺序为：

```text
阶段 0：冻结范围
    -> 阶段 1：E2/E3/E5A pretrained-vs-random 归因
    -> 阶段 2：E2/E3/E5A 检索可视化
    -> 阶段 3：两种下游宿主的集成验证
    -> 阶段 4：最多一次单变量模型调整
    -> 阶段 5：冻结配置并运行最终 test
```

任何阶段未通过门槛，都必须执行对应的 `Keep / Remove / Stop` 决策，不能用新增复杂模块掩盖失败结果。

## 2. 三个保留版本分别是什么

### 2.1 统一数据契约

METR-LA 每个时间步为 5 分钟。三个版本的下游预测输入和输出保持一致：

- 检索历史 `retrieval_history`：`[B, 288, N, 1]`，表示最近 24 小时，用于生成 retrieval key；
- 下游历史 `history`：`[B, 12, N, 1]`，表示最近 60 分钟，用于下游预测；
- 预测目标 `future`：`[B, 12, N, 1]`，表示未来 5 至 60 分钟；
- 检索 memory：`[B, 12, N, 1]`，表示由历史 Bank 聚合得到的未来参考。

其中 `B` 为 batch size，`N` 为传感器节点数，最后一维 `1` 为交通速度通道。

### 2.2 E2：长历史检索表示

`E2` 使用 288 步、即一天历史生成检索 key，并沿用 E2 已有的 future-guided 预训练目标。它的主要研究问题是：

> 更长的历史是否能帮助 selector 判断当前交通状态属于哪一种历史演化模式？

E2 的下游 backbone 仍只读取最近 12 步，不把一天历史直接输入预测主干。因此 E2 的额外历史只服务于检索，不改变短期预测输入。

### 2.3 E3：RawFuture relation teacher

`E3` 使用连续 future relation 监督 selector。训练时，teacher 根据 source-train 样本之间的真实 future 距离构造软关系；student 只根据历史 context 生成 key，并学习复现该关系。

E3 的关键边界是：训练 teacher 可以读取 source-train future 来定义监督关系，但 encoder 输入始终只有历史；部署时不读取当前 query future。

E3 的历史 Bank 保存的是已经完整发生的历史事件，其 future 在当前 query 时刻已经属于过去，不构成未来泄漏。

### 2.4 E5A：与 OffsetDecay 部署方式对齐的 relation teacher

本文后续统一把 E5 的保留版本称为 `E5A`。E5A 不增加推理网络，只把 E3 的 raw-future teacher 改成与部署期 `OffsetDecay` 一致的 teacher。

对 source-train 事件 \(i\)，E5A 的训练期 future signature 为：

\[
S^{\mathrm{OD}}_{i,h,n,c}
=
Y_{i,h,n,c}-\lambda_h\alpha_{i,n,c}.
\]

其中：

- \(Y_{i,h,n,c}\) 是训练事件 \(i\) 在预测步 \(h\)、节点 \(n\)、通道 \(c\) 的真实 future；
- \(\alpha_{i,n,c}\) 是事件 \(i\) 最近 12 个可见历史步的平均速度 level；
- \(\lambda_h=1-(h-1)/(H-1)\) 是随预测距离线性衰减的权重；本项目 \(H=12\)。

该 signature 只在 source-train teacher 中使用，并在 `torch.no_grad()` 下构造。推理时不构造 query 的 \(S^{\mathrm{OD}}\)，也不读取 query future。

`OffsetDecay` 是部署期历史 future 的零参数对齐方式，不是神经网络。Bank 中仍保存 raw historical future，检索后再计算：

\[
\widehat Y^{\mathrm{OD}}_{q,h,n,c}
=
\widehat Y^{\mathrm{raw}}_{q,h,n,c}
+\lambda_h
\left(
\widehat Y^{\mathrm{offset}}_{q,h,n,c}
-\widehat Y^{\mathrm{raw}}_{q,h,n,c}
\right).
\]

这里：

- \(\widehat Y^{\mathrm{raw}}\) 是 selector 对历史 raw future 的加权聚合；
- \(\widehat Y^{\mathrm{offset}}\) 先减去候选历史 endpoint level，再加上当前 query 的历史 level；
- 输出 \(\widehat Y^{\mathrm{OD}}\) 的形状为 `[B, 12, N, 1]`；
- 当前 query 的 level 来自已观察历史，不使用 query future。

### 2.5 Random selector：零训练步的同构随机对照

`Random selector` 指与对应 pretrained selector 结构、参数量、输入、Bank 构建规则和检索规则完全相同，但 encoder 和 retrieval head 从未执行训练更新的模型。checkpoint 中必须满足 `trained_steps=0`。

Random 对照不是随机抽取历史 future。它仍然用同一个固定随机映射编码 query 和 Bank 事件，再按 key 相似度排序。因此它回答的是：

> 预训练学到的关系是否优于同构随机特征所保留的输入几何关系？

## 3. 范围冻结

### 3.1 本轮保留

| 版本 | 保留机制 | 下游 memory | 研究作用 |
|---|---|---|---|
| E2 | 一天历史检索表示 | RawFuture | 验证长历史是否提供检索价值 |
| E3 | RawFuture relation teacher | RawFuture；另做 OffsetDecay 诊断 | 验证连续 future relation 预训练 |
| E5A | ODSignature relation teacher | OffsetDecay | 验证训练 teacher 与部署 payload 对齐 |

版本内部的 pretrained-vs-random 对照使用该版本的正式 payload。E3 与 E5A 的 teacher 单变量比较则必须固定相同的 OffsetDecay payload，只把 E3 selector 换成 E5A selector；不能用“E3 RawFuture 对 E5A OffsetDecay”证明 teacher 更好，因为这会同时改变 selector 和 payload。现有 E5A 阶段报告已经采用相同 OffsetDecay payload 完成了该项比较。

### 3.2 本轮冻结，不再继续扩展

- E4；
- E5 FutureIncrement/T1-B；
- 线性趋势残差和复杂趋势分解；
- confidence 主线；
- GCRU/DCD-ST 等新 backbone 复现；
- 多源联合预训练；
- 新的 attention、频域、prototype 或 adapter 分支。

已有趋势残差实验在 METR-LA 和 PEMS-BAY 上均明显恶化，因此当前没有证据支持继续增加趋势模块。若后续出现明确失败样本，只允许在阶段 4 做一次单变量修正，不能重新打开整条复杂模型路线。

## 4. 所有实验必须统一的控制条件

同一版本的 pretrained 和 random 只允许 checkpoint 参数是否经过预训练这一项不同：

- 相同数据划分、scaler、图和传感器集合；
- 相同 288 步 retrieval history 和 12 步 downstream history；
- 相同 Bank 事件范围和 `memory_fraction=0.7`；
- 相同 `event_top_r=32` 和 `node_top_k=5`；
- 相同候选日历过滤和 future non-overlap 因果过滤；
- 相同下游 backbone、训练 epoch、early stopping 和 seed；
- E2 使用 E2 冻结配置；E3/E5A 使用 `level_weight=0` 的 Level-0 配置；
- 主归因实验关闭 confidence，只使用 horizon-only fusion；
- 不使用 `--max-batches` 或 `--max-events` 生成正式结果。

`Horizon-only fusion` 表示只为 12 个预测步各学习一个融合上限，不使用节点级 confidence head。设下游预测为 \(\widehat Y^{\mathrm{base}}_h\)，memory 为 \(\widehat Y^{\mathrm{mem}}_h\)，则：

\[
\widehat Y_h
=
\widehat Y^{\mathrm{base}}_h
+a_h
\left(
\widehat Y^{\mathrm{mem}}_h-
\widehat Y^{\mathrm{base}}_h
\right),
\]

其中 \(a_h\in[0,1]\) 只与预测步 \(h\) 有关。该方式只增加 12 个可训练标量，用于隔离 memory 的贡献。

### 5.10 阶段 1 的指标和判断门槛

预测指标统一在还原到交通速度物理单位后计算。设有效元素集合为 \(\Omega\)，真实值为 \(Y_i\)，预测值为 \(\widehat Y_i\)：

\[
\mathrm{MAE}
=\frac{1}{|\Omega|}\sum_{i\in\Omega}|Y_i-\widehat Y_i|,
\]

\[
\mathrm{RMSE}
=\sqrt{\frac{1}{|\Omega|}\sum_{i\in\Omega}(Y_i-\widehat Y_i)^2},
\]

\[
\mathrm{MAPE}
=\frac{100}{|\Omega_{\%}|}
\sum_{i\in\Omega_{\%}}
\left|\frac{Y_i-\widehat Y_i}{Y_i}\right|.
\]

其中 \(\Omega_{\%}\) 还要排除不满足 MAPE 分母条件的元素。必须报告：

- overall MAE、RMSE、MAPE；
- 12 个 horizon 的 MAE、RMSE、MAPE；
- 15、30、60 分钟三组重点指标；
- memory coverage；
- pretrained 相对 random 的绝对差和相对改善；
- base branch、memory branch 和 final branch；
- node-wise MAE 分布和误差最高的 10 个节点，判断收益是否只集中在少数传感器；
- 参数量、每轮时间、推理延迟和 peak GPU memory。

阶段 1 的版本门槛：

1. pretrained memory MAE 必须优于 random memory MAE；
2. pretrained final MAE 至少不劣于 random final MAE；
3. 12 个 horizon 中多数 MAE/RMSE 方向不能恶化；
4. 相比 base-only 必须出现可重复的正向收益，不能只依赖某一个 horizon；
5. confidence head 参数和 confidence loss 必须均为 0。

决策：

- 检索层和下游层都通过：`Keep`，进入可视化和第二下游；
- 检索层通过、下游层未通过：保留为“有效检索表示”，但不作为最终预测模型主版本；
- pretrained 不优于 random：`Remove from main claim`，停止该版本多 seed 和多下游扩展；
- random 和 pretrained 都优于 base-only，但彼此持平：只能声称历史 memory 有效，不能声称预训练有效。

### 5.11 多 seed 补充规则

只有通过 seed 42 门槛的版本补 downstream seed `2024、2025`。先固定同一个 pretrained checkpoint 和 Bank，只改变下游初始化，以判断下游收益稳定性。若最终论文需要声明预训练稳定性，再单独训练 pretraining seed `2024、2025`，两类随机性不能混在同一张表中。

## 6. 阶段 2：检索可视化实验

### 6.1 实验动机

数值指标只能说明预测误差变小，不能直接展示 selector 学到了什么。本阶段只回答一个可审计的问题：预训练后的历史编码器，是否比同构 random 初始化编码器更容易把“未来模式相似”的历史事件映射到相近的 node key。可视化不是展示模型复杂度，而是检查以下科学假设：

1. pretrained selector 是否比 random 检索到 future 更相似的历史事件；
2. E2 的一天历史是否检索到具有相似周期背景的事件；
3. E3 是否学到“历史 context 可以不同，但后续 future 相似”的时空海市蜃楼关系；
4. E5A 的 OffsetDecay 是否在保留未来变化形状的同时修正当前 level 偏差；
5. E5A 的 payload 修正是否在同一组检索候选上改善物理量预测。

### 6.2 Future 信息边界

可视化只使用 validation split：

- query history、Bank key、候选过滤和 selector 排序只能使用部署期可用信息；
- query true future 只允许在检索完成后用于离线画图、着色和误差标注；
- query true future 不得进入 key、候选选择、Top-K 权重或预测；
- future-oracle 只能标记为 `diagnostic-only upper bound`，不能作为可部署方法。

### 6.3 已执行的最小证据

本实验只读取已有 checkpoint、历史 Bank 和 validation split，不训练新模型。为避免把复杂图形误当成机制证据，正式结果固定为两类图：

1. **Key-Future Alignment**：把同一合法候选池中的 `(query,node,candidate)` 对按 node-key 距离分成 10 个等频区间，画每个区间的 teacher-aligned future distance 均值曲线，并并列报告 Spearman 和 Future-Neighbor Recall@5。
2. **Deterministic Top-5 Cases**：按 `Delta MAE = random memory MAE - pretrained memory MAE` 的 90%、50%、10% 分位点确定 `strong_win`、`representative`、`failure` 三个案例，画 query true future、pretrained/random memory 和对应候选 future。案例 id、候选 id、权重和选择规则写入 JSON，禁止人工挑例。

E5A 额外输出 **OffsetDecay payload** 图：固定同一 pretrained selector 和同一 Top-5 候选，只比较 RawFuture memory 与 OffsetDecay memory；payload 案例按 `RawFuture MAE - OffsetDecay MAE` 的 90%、50%、10% 分位点独立选择，不能复用 selector 对比案例。

### 6.5 指标和判定规则

- **Spearman 秩相关**：对所有有效候选对计算 `rho = corr(rank(d_key), rank(d_future))`。正值越大，表示 key 越远时 future 通常越不相似；它是关系对齐指标，不是预测误差。
- **Future-Neighbor Recall@5**：对候选数大于 5 的 anchor，分别取 future distance 最近 5 个和 key distance 最近 5 个，计算两集合交集大小除以 5，再对 anchor 平均。候选池平均约 8 个，因此绝对值偏高，重点看 pretrained-relative-to-random 差值。
- **Memory MAE/RMSE/MAPE**：在物理速度单位上，对检索 memory 与 query true future 逐元素计算平均绝对误差、均方根误差和百分比误差；只作离线诊断，不参与排序。
- **Keep**：pretrained 的 Spearman、Recall@5 和 memory 误差均优于 random，且 key-distance decile 曲线总体单调；
- **Weak evidence**：仅关系指标或仅预测指标改善，保留为辅助证据，不扩大主张；
- **Remove from main claim**：pretrained 不优于 random，或只有手工/个别案例成功。

当前三版都满足关系指标方向，E5A 还显示 OffsetDecay payload 的独立收益；因此阶段 2 结论为 `Keep as mechanism evidence`，不新增趋势分解、confidence 或 backbone 模块。

### 6.6 E5A 候选协议归因补充实验

为判断 ExactCalendar 的平均 8 个候选是否限制 E5A，固定 checkpoint、Bank、Top-5、OffsetDecay 和 validation split，只比较三种协议：ExactCalendar（相同星期和时间槽）、RelaxedCalendar（相同星期、时间槽前后 5 分钟）和 BroadCausal（全因果 Bank 中按时间轴均匀抽取 32 个，只作诊断上限）。三种协议的含义、输入输出、公式和 future 信息边界见 `doc/诊断报告合集/E5A候选协议归因诊断报告.md`。

结果表明，候选池从 Exact 的 8.014 扩展到 Relaxed 的 23.985 后，pretrained MAE 从 3.527230 降到 3.472132，Spearman 从 0.318104 升到 0.328968。BroadCausal 的 pretrained Spearman 达到 0.674464，但 MAE 3.512407、MAPE 9.818750 未优于 Relaxed/Exact，因此它只能证明更宽候选能暴露关系能力，不能直接成为部署协议。

决策：`Keep RelaxedCalendar for downstream validation`；`BroadCausal diagnostic only`；不因候选归因实验增加模型结构。

## 7. 阶段 3：多下游模型集成验证

### 7.1 实验动机

当前 STAnchor 轻量 backbone 上的收益可能来自某一特定融合结构。多下游验证要回答：

> 同一个 frozen selector 和 frozen Bank，能否在不同预测主干上提供方向一致的增益？

本轮只选两个宿主，避免重新扩大工作量。

### 7.2 宿主 A：当前 STAnchorDownstreamModel

`STAnchorDownstreamModel` 是当前已经接通的轻量预测主干。阶段 1 的 base-only、pretrained 和 random 结果直接作为宿主 A 结果，不重复训练。

### 7.3 宿主 B：STSSDLBaseline

`STSSDLBaseline` 位于 `TrafficRobustST/src/models/stssdl_baseline.py`，是当前已有 ST-SSDL 论文基线实现。它作为第二个独立宿主，不重新设计 backbone。

统一接入方式为：

```text
STSSDL history input [B, 12, N, 1]
    -> STSSDL base prediction [B, 12, N, 1]
frozen STAnchor selector + frozen Bank
    -> retrieval memory [B, 12, N, 1]
base prediction + horizon-only fusion
    -> final prediction [B, 12, N, 1]
```

STSSDL 内部结构和原损失保持不变，只在预测输出后增加与宿主 A 相同的 12 个 horizon fusion 标量。不得加入 confidence、cross-attention 或新的 memory encoder。

### 7.4 需要新增的最小适配入口

在运行宿主 B 前，需要实现：


适配器必须复用现有 Bank reader、causal candidate filter、selector 和 OffsetDecay 实现，不能复制出第二套检索逻辑。归一化必须明确：STSSDL base prediction 和 STAnchor memory 在融合前必须位于同一物理量或同一标准化空间。

### 7.7 多下游判断规则

- 两个宿主中 pretrained 均优于 random，且均不劣于 base-only：可支持“模型无关的检索增强”主张；
- 只有宿主 A 有效：只能声称对当前轻量下游有效，不得写成通用插件；
- memory branch 有效但 final 无收益：说明融合或信息重叠是瓶颈，不说明 selector 无效；
- random 在任一宿主稳定优于 pretrained：该版本不能作为预训练创新主结论；
- 第二宿主需要大幅改动 backbone 才有效：停止该路线，不用复杂集成补救。

## 8. 阶段 4：根据证据进行最多一次调整

本阶段不是必做的“继续改模型”，而是根据前三阶段只关闭一个明确不确定性。一次实验只能改变一个变量。

| 观察信号 | 允许的最小调整 | 禁止动作 | 决策 |
|---|---|---|---|
| pretrained memory 优于 random，但 final 与 base-only 接近 | 检查 12 个 horizon fusion 权重和 base-memory 误差互补性；必要时只调整 fusion 初始化 | 加 confidence 或 cross-attention | 若仍无收益，保留检索分析但不作为最终预测模型 |
| E5A 仅远期恶化 | 只比较一次固定线性衰减与无衰减，不训练新网络 | 加趋势分解网络 | 无稳定改善则保留当前线性 OffsetDecay |
| pretrained 与 random 持平 | 不调整下游，停止该版本预训练主张 | 扫描大量 Top-K、温度或新损失 | 从论文主版本移除 |
| 两个宿主方向一致 | 不再修改模型 | 为追求更大数字继续堆模块 | 直接冻结并进入 test |

默认优先级是“能不改就不改”。如果 E5A 已在 random、可视化和两个宿主上形成一致证据，则阶段 4 直接记为 `No structural adjustment`，这比新增一个难以解释的模块更有利于论文主线。

## 11. 最终论文主线选择规则

最终版本按以下顺序选择，不能只看单一最佳 MAE：

1. pretrained 是否稳定优于同构 random；
2. memory 是否优于 base-only；
3. 两个下游宿主是否方向一致；
4. 可视化是否支持“future-guided retrieval”机制解释；
5. 参数量、训练和推理成本是否可控；
6. 最后才比较 E2、E3、E5A 的绝对性能。

推荐的论文叙事保持简单：

```text
问题：相似历史 context 不一定对应相似 future，传统历史匹配会出现时空海市蜃楼。
核心方法：使用训练期 future relation 引导只读取历史的 selector。
部署机制：从因果历史 Bank 检索已发生 future，并用轻量 payload 对齐后辅助预测。
关键证据：pretrained-vs-random、检索可视化、两种下游宿主和多 seed。
```

E2、E3、E5A 不必都成为最终模型。它们可以形成清晰的演进消融：长历史表示 -> raw-future relation -> deployment-aligned relation。最终只保留证据最完整且复杂度最低的版本作为主方法。
