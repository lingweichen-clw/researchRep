# 检索增强下游门槛实验步骤

## 1. 本阶段只回答什么问题

本阶段不重新预训练 encoder，不重新构建 Bank，也不增加 selector 或损失函数。当前只运行现有的 `learned weighted top-K` 完整下游链路，确认：

> 已预训练 encoder、历史块检索、置信度估计和安全融合接入轻量预测 backbone 后，能否稳定完成训练，并得到可复现的 validation 结果？

这是一组进入最终四项下游对照实验之前的**门槛实验**，不是最终消融结论。当前代码尚未提供 `base only`、`weekly mean` 和 `raw L1 top-K` 的命令行切换参数，因此不能用本次单组结果证明 learned retrieval 优于这些下游基线。

## 2. 已确认可复用的实验产物

下列两个产物已经存在，本阶段直接复用：

| 产物 | 路径 | 用途 |
|---|---|---|
| patch3 最优预训练 checkpoint | `artifacts/metrla_pretrain_seed42/pretrain_best.pt` | 提供冻结的 encoder 与 retrieval head |
| METR-LA 完整历史 Bank | `artifacts/metrla_bank_v1` | 提供历史 context、future、event key、node key 与统计特征 |

## 4. 正式训练 learned weighted top-K 下游模型

执行：

```powershell
python scripts/train_downstream.py `
  --config configs/metrla_v1.yaml `
  --pretrained-checkpoint artifacts/metrla_pretrain_seed42/pretrain_best.pt `
  --bank artifacts/metrla_bank_v1 `
  --run-name metrla_learned_topk_downstream_seed42
```

该命令会执行以下固定流程：

1. 冻结预训练 encoder 与 retrieval head；
2. 从完整 Bank 中执行节点级 top-K 检索，其中 $K=5$；
3. 使用 learned score 的 softmax 权重聚合五个候选 future；
4. 训练轻量预测 backbone、confidence head 和 safe fusion；
5. 以 validation MAE 选择 `downstream_best.pt`，patience 为 10。

正式实验不要添加 `--max-batches`，也不要使用 `--epochs` 覆盖配置。它们只用于代码调试，会让结果不再是完整实验。

训练期间控制台和文件都会输出日志。另开一个 PowerShell 终端可实时查看：

```powershell
Get-Content `
  artifacts\metrla_learned_topk_downstream_seed42\downstream.log `
  -Tail 30 -Wait
```

训练完成后应生成：

```text
artifacts/metrla_learned_topk_downstream_seed42/
|-- downstream.log
|-- target_metrics.jsonl
`-- downstream_best.pt
```

## 5. 只在 validation 集上正式复评

训练结束后执行：

```powershell
python scripts/evaluate.py `
  --config configs/metrla_v1.yaml `
  --pretrained-checkpoint artifacts/metrla_pretrain_seed42/pretrain_best.pt `
  --downstream-checkpoint artifacts/metrla_learned_topk_downstream_seed42/downstream_best.pt `
  --bank artifacts/metrla_bank_v1 `
  --split val `
  | Tee-Object -FilePath artifacts\metrla_learned_topk_downstream_seed42\val_evaluation.json
```

重点保留以下结果：

- `metrics.mae`：最终融合预测的 validation MAE，越低越好；
- `metrics.rmse`：对较大误差更敏感的 validation RMSE，越低越好；
- `metrics.mape`：相对误差，只作为辅助指标；
- `confidence_loss`：置信度头是否学会区分历史聚合“有帮助”和“无帮助”的训练代理损失；
- `epoch` 与 `best_val_mae`：从 `downstream.log` 中记录最优轮次和早停情况。

这里的 MAE/RMSE/MAPE 是完整下游最终预测指标，不能与诊断报告中的 `retrieved future MAE=3.9047` 直接等同。后者只评估历史 future 本身，不经过 backbone、confidence 和 fusion。

## 6. 本轮停止条件与决策

完成 validation 复评后立即停止，不改模型，不运行 patch1，也不提前查看 test 集。

按下列规则决定下一步：

| validation 现象 | 决策 |
|---|---|
| loss 有限、正常早停、结果可复现 | 保留该 checkpoint，下一步只实现最小的四模式下游对照接口 |
| confidence loss 几乎不变化，且融合结果表现异常 | 先诊断 confidence/fusion，不修改 encoder 或检索库 |
| 训练不稳定、出现 NaN、Bank/checkpoint 校验失败 | 视为工程阻塞，先修复，不进入对照实验 |

下一步需要验证的最终科学问题仍然是：在完全相同的轻量 backbone、数据划分和随机种子下，`learned weighted top-K` 是否稳定优于 `base only`、`weekly mean` 和 `raw L1 top-K`。当前脚本没有这些模式开关，因此本轮结束后应先查看本轮日志，再决定是否实现这一处最小接口；不要提前扩展新模块。
