# E2、E3、E5A 检索可视化实验实施计划

## 1. 实验目标

本实验只回答一个问题：预训练后的历史编码器，是否比同构 random 初始化编码器更容易把“未来模式相似”的历史事件映射到相近的 node key。

实验不训练新模型，只读取已有 checkpoint、历史 Bank 和 validation split。query true future 只在历史候选排序完成后用于离线评价和画图，不进入 key 编码、候选过滤、Top-K 排序或权重计算。

## 2. 特殊名词和计算定义

### 2.1 合法历史候选集合

合法历史候选集合是与 query 具有相同星期和时刻、且候选 future 已经在 query context 开始前完全发生的 Bank 事件。输入为 query 的星期、时刻和 `context_start`，输出为事件编号集合。它只使用部署时可获得的时间信息，不读取 query future。

### 2.2 KeyDistance：node key 距离

对 query-node key `k_q` 和历史候选 node key `k_j`，定义：

\[
d^{key}_{qjn}=1-\cos(k_{qn},k_{jn}).
\]

输入 key 形状分别为 `[B,N,D]` 和 `[B,R,N,D]`，输出为 `[B,N,R]`。`B` 是 query batch，`N` 是节点数，`D` 是 key 维度，`R` 是相同合法候选池中的候选数。距离越小表示编码器认为两者越相似。

### 2.3 TeacherAlignedFutureDistance：与各版本训练 teacher 对齐的 future 距离

该距离只用于离线验证 key 是否学到目标 relation。

- E2、E3 使用 `ContextNormalizedFutureSignature`：每个事件的 future 用该事件 288 步历史 context 的均值和标准差归一化，再计算 query 与候选在共同观测位置上的 MAE。
- E5A 使用 `ODSignature`：`S_h=Y_h-lambda_h*alpha`，其中 `alpha` 是该事件预测起点前 12 步 context 的末端 level，`lambda_h` 从第 1 个 horizon 的 1 线性衰减到第 12 个 horizon 的 0；再计算 query 与候选 signature 在共同观测位置上的 MAE。

输入为 query future `[B,H,N,C]`、候选 future `[B,R,H,N,C]` 及对应 mask，输出 future 距离 `[B,N,R]`。`H=12`，`C=1`。训练时 future 是 teacher 监督；推理时不计算该距离；本实验只在历史排序结束后读取 validation query future。

### 2.4 Key-Future Alignment：key 与 future 的一致性

把所有有效 `(query,node,candidate)` 对按 `KeyDistance` 从小到大分成 10 个等频区间，分别统计每个区间的 future 距离均值和中位数。如果较近 key 的 future 距离明显更小，说明 key 空间与目标 future relation 对齐。

同时报告：

- `Spearman`：`KeyDistance` 与 future 距离的秩相关系数。正值越大，说明 key 越远时 future 通常也越不相似。
- `Future-Neighbor Recall@5`：对至少有 6 个合法候选的 query-node，取 future 距离最近 5 个作为离线真值集合，取 key 距离最近 5 个作为预测集合，计算交集比例。该指标只验证邻居关系，不能在部署时计算。

预训练和 random 始终使用相同的合法事件编号，避免候选池差异污染对比。

### 2.5 DeterministicCaseSelection：确定性案例选择

先按两个模型各自的真实部署评分检索 Top-5 并形成加权 memory，然后计算每个 query-node 的：

\[
\Delta MAE=MAE_{random}-MAE_{pretrained}.
\]

从所有共同有效 query-node 中，固定选择最接近 `Delta MAE` 的 90%、50%、10% 分位点的三个样本，依次称为 `strong_win`、`representative`、`failure`。输出 query id、节点 id、时间、候选 id、权重和选择规则 JSON，禁止人工换样本。

### 2.6 OffsetDecay Memory

OffsetDecay 不是神经网络。对 E5A 已检索的候选 future，先把候选起点 level 对齐到 query 起点 level，再让该修正从近端到远端线性衰减：

\[
\widehat Y_h^{OD}=\widehat Y_h^{raw}+\lambda_h
(\widehat Y_h^{offset}-\widehat Y_h^{raw}).
\]

输入为同一批 Top-5 候选、候选权重、query 最近 12 步 context 和候选最近 12 步 context，输出为 `[B,H,N,C]`。推理只读取 query history 和已经发生的 Bank 历史，不读取 query future。E5A 额外画同一候选集合的 RawFuture memory、OffsetDecay memory 与 true future。

## 3. 文件结构

- 新增 `stanchor/diagnostics/retrieval_visualization.py`：纯统计、确定性选择、全量 validation 执行和正式结果保存。

- 新增 `doc/诊断报告合集/E2-E3-E5检索可视化诊断报告.md`：记录动机、指标、结果、信号和 Keep/Remove 决策。

## 4. 测试驱动实施顺序

1. 先为 masked future MAE、两类 signature、等频分箱、Spearman、Recall@5、分位点案例选择和 future 边界元数据写单元测试。
2. 运行 `python -m unittest tests.test_retrieval_visualization -v`，确认测试因模块不存在或函数未实现而失败。
3. 实现最小统计函数并再次运行该测试。
4. 实现全量 validation runner 和绘图入口，运行 one-batch smoke。
5. 删除带 `smoke` 或 `max_batches` 标记的临时目录。
6. 顺序运行 E2、E3、E5A 完整 validation，不使用 `--max-batches`。
7. 检查 JSON 中 query 数、有效 pair 数、未来边界声明和三个案例 id；打开 PNG 核对非空、曲线和文字没有遮挡。

## 6. 判定规则

- `Keep`：预训练 Spearman 和 Recall@5 均优于 random，且 10 个 key-distance 区间总体呈正向关系；案例图方向与全量指标一致。
- `Weak evidence`：仅一个全量指标改善或改善很小；保留为辅助证据，不扩大主张，并补多 seed 后再决定。
- `Remove from main claim`：预训练不优于 random，或只存在个别成功案例而全量统计不支持。
- E5A 的 RawFuture 与 OffsetDecay 对比只评价 payload 对齐，不代替 selector 的 pretrained-vs-random 归因。
